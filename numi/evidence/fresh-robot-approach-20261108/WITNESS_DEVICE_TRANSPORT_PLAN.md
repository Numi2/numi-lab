# Witness private-buffer transport: bounded diagnostic

Question: can the exact captured entry rod-witness buffer survive a Metal shared-to-private upload and private-to-shared readback, with mismatch detected before output publication? This is a transport instrument test only, not an owner-state import, resume, complete checkpoint, atomic transaction, force or biological qualification.

Use the 48,956-slot raw entry witness artifact from `rod-witness-readback-001`, SHA-256 `1f7f8d63c81b12f7ba4c1fb8a300fe38408ce1d1e94b98dd89376bb753bfcdca`. Positive mode must complete the device command, match every byte and publish an output whose SHA-256 equals the input. Negative mode intentionally flips one staged byte before upload while comparing against the unchanged input; it must exit 6 with `bytes_equal=0` and publish no output. A bad input length and argument error must reject before Metal initialization. Record exact native source, executable, input and resulting output hashes, timestamps, exit status, and all logs. Run only these two bounded modes on the same pinned device input and preserve either failure. Do not reinterpret corruption rejection as proof of owner import or automatic rollback.
