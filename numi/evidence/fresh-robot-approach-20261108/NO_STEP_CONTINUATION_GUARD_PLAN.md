# Seeded-owner configuration guard: preregistration

The narrow no-step seed records the fingerprint of the solver and context configuration used to create its fresh owner. Before reserving or mutating a seeded resident, a subsequent submission must reject a different fingerprint while retaining the valid owner; ordinary residents retain their existing behavior. Repeat the separately pinned populated-convex/manifold fixture and its negative, injected post-completion mismatch, device-readback and retry checks. Attempt a changed-velocity-iteration continuation, require rejection, no valid submission ticket and an intact seeded resident, then submit the original configuration and require the same one-step q/v, convex cache and complete manifold bytes as the uninterrupted owner. All failures must be retained. This is a rigid-only diagnostic and does not establish actual Metal execution failure, long-horizon replay, coupled restoration, or surgical validity.
