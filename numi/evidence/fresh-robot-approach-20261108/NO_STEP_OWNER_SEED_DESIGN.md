# No-step resident seed and device-readback design

Status: proposed diagnostic only. The standalone private-buffer round-trip does not import a MetalWorld owner. The existing step-1645 checkpoint plus two contact caches still does not prove complete owner state; no claim below upgrades it.

## Existing boundary and concrete blockers

`MetalWorldContext::initializeResidentState` calls `submitImpl`; `validateAndBuildLayout` explicitly rejects `controlStepCount == 0`, and initialization continues into a physics graph. `uploadBatch` seeds q/v, scene and optional rigid manifolds, while `encodeResidentStateInitialization` unconditionally clears both rod-witness buffers and convex caches. The batch has no initial rod-witness span. Consequently neither a zero-step call nor passing a synthetic one-step command can prove the untouched imported device state. The standalone transport control verifies Metal byte movement but does not change any of these facts.

`MetalWorldResidentStateData` retains the context/pool, `pending`, arena generation, fingerprints and active q/v, scene, manifold, rod-node, rod-edge and rod-witness buffer selectors. On completed submission `finishResident` publishes those selectors. The existing initializer and submit path use the resident mutex and arena `inFlight` reservation, then transfer lifetime to `MetalWorldSubmission`; its destructor waits for completion before releasing the arena. The currently retained v3 TSV names the model and binds the Matter snapshot, but does not record the compiled MetalWorld fingerprint; do not invent a historical fingerprint or treat a fingerprint from a later recook as evidence of the original value. A new source-bound capture must record that identity at the accepted boundary. A new seed operation must use compatible ownership and cannot expose a candidate token while an upload/readback is incomplete. Matter has a separate `commandOwnership` gate, so successful MetalWorld seeding is not an atomic Matter+MetalWorld import.

## Smallest legitimate owner diagnostic

1. Add a separate, narrowly scoped diagnostic entry point `seedResidentNoStep` for one environment and the supported surgery configuration. It takes a versioned immutable state capsule and produces an unpublished candidate; it must not call `submitImpl` with a fake positive step count, issue control/reset masks, or invoke the device-physics callback. Build a real seed-only requirements/layout path sharing validated shape/capacity functions without weakening nonzero-step validation for normal submissions.
2. Validate before device access: model, world/topology, device program and ABI identities; exact environment/capacity/length; rigid and rod layout; finite q/v/body/rod values; active manifold identity/generation; and each active rod witness pair/collider/topology generation and impulse finiteness. Bind the saved witness raw bytes to the exact entry checkpoint TSV hash and step, saved Matter payload hash, compiled-world fingerprint and device program. Reject missing, substituted, truncated, oversized, wrong-revision and mixed-capsule inputs. A content hash detects accidental mismatch; independent SHA-256 manifests remain part of provenance.
3. Reserve a fresh context arena and unpublished candidate with the established pool/context and resident lifetime rules. Upload canonical q/v, bodies, rod nodes/edges, manifold cache and rod witnesses to designated active buffers; initialize inactive/scratch buffers explicitly. Audit `kConvexCaches`, reset streams and every other configured persistent arena. Either seed every field needed by the selected configuration or return an explicit partial/unsupported status. Do not present this first witness-focused diagnostic as complete-owner restore while any field is unresolved.
4. After upload and before any physics, encode private-to-shared readbacks in the same command buffer for each imported buffer, including rod witnesses. Wait for command completion and validate mapped capacity. Compare every returned byte against the capsule before publishing the candidate token. A failed allocation, encoder, command, mismatch or timeout must publish no candidate. Keep all borrowed buffers and ownership alive until completion; invalidate and dispose the candidate rather than resuming an arena whose upload/verification failed. A host timeout cannot release a live command or imply completion. Detect and report cleanup/failure separately.
5. Test a valid seed with exact device readback, and inject truncated, one-bit, identity, generation and device-failure cases; verify no candidate token or physical step is published on failure. Then, separately, attach the matching Matter runtime and submit one bounded continuation only when the surrounding owner can reserve both authorities and prove their shared transaction epoch. Compare with the previously retained same-resident control, including q/v, body, rod witnesses, normal/tangential response and Matter authority. Until a shared reservation/atomic publish protocol exists, this last coupled test remains explicitly non-atomic and cannot be called full restoration.

The diagnostic must retain the existing puncture/contact gates and its accepted-state/failure provenance. Solver reaction errors and synthetic material remain independent physical limitations.
