# Canonical deep attachment rebinding

This native import increment preserves all fourteen immutable attachment IDs and donor bodies while keeping their original elastic area and stiffness. A derived current D vertex has its own source namespace. It must resolve through the exact surface/volume row, donor/frame/mass owner and an authenticated source-330 parent-star lineage. Historical registration is distinct from current operational reference support.

For a canonical remap, only the old rest point and normal are rebound to the current donor-local reference. The force law and area remain unchanged, so matched displacement has the same force and energy with no introduced reference prestress. Exact inherited rows keep their existing byte parity. Canonical remaps are not new attachment samples; only the new-site spacing rule is inapplicable, while the original ID/body inventory, per-body count, source lineage, donor confidence and incident-cell quality checks remain mandatory.

The native Metal elastic branch uses force = stiffness.x * area * gap and energy = 0.5 * stiffness.x * area * dot(gap,gap). The second stiffness component scales a diagnostic strain; it is not an additional force term.

The assert-enabled and ASan/UBSan checks pass, including real canonical tuples, wrong identity/domain/lineage rejection, numeric namespace collision, zero rest prestress and matched displacement force/energy parity. The exact patch against published main compiles and links as the native Human executable on SSH Numi. The build script, command arguments and hashes are retained here. No Runtime was created and no physical step was accepted.

The changed-topology mass route remains source-only gated. Completion still requires the current 149-target geometry packet, retetrahedralized skin/fat cells, mass and detailed-transfer admission, and native motion checks. This increment is not physical or motion qualification.
