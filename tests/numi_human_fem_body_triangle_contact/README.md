# Human FEM-node / moving-bone triangle contact regression

From the repository root, run this against a fresh output directory:

```sh
python3 tests/numi_human_fem_body_triangle_contact/run.py \
  --build-dir /tmp/numi-human-bone-triangle-contact-run-001
```

The entrypoint builds and runs the CPU oracle, syntax-checks the production owner and existing surface-attachment coupon, compiles the Metal coupon and metallib, and runs its production-kernel cases. The receipt includes the source revision, source and binary hashes, commands, logs, and elapsed time. For isolated source-overlay checks, the same entrypoint accepts `--source-overlay PATH --base-root REPOSITORY`.

The optional triangle table is an immutable, body-local prepared bank with a per-sample maximum query distance. The selector searches only that bank and fails closed when the accepted node leaves either the declared body-local motion ball or the bank distance bound. This does not search the full bone mesh each step and does not prove the bank contains the globally nearest face or all anatomically relevant faces. It is a local owner-kernel regression, not a global collision, anatomical-coverage, integrated-scene, or natural-range-of-motion qualification.

The CPU preparation helper appendCompleteNeighborhood accepts an explicitly complete registered triangle inventory for one body, its declared inventory count, a body-local rest position, and a Euclidean motion radius. It sets an explicit ABI-15 motion-envelope mode in each produced range and stores the body-local rest point plus motion radius. The shared GPU selector fails closed whenever the current body-local query is farther than that radius (plus a rest-scale Float32 guard), before running the same deterministic closest-triangle selection used by force, wrench, audit, and provisional-status consumers. The producer includes every face whose rest-point distance is at most d_min + 2(R + envelopeGuard) + geometryGuard. A rest-nearest face remains within d_min + R + envelopeGuard over the guarded motion ball, while any omitted face remains farther, so the prepared winner is complete for closest-face queries inside that declared envelope. It fails without partial output on count/identity/geometry errors, more than 128 required faces, or a certified query bound above the existing 50 mm runtime limit; it never truncates. Completeness is only relative to the caller-supplied inventory and is not proof that the inventory covers all anatomical bone faces. Host Source validation rejects unknown modes, malformed envelopes, nonzero legacy extension lanes, and envelope radii larger than their certified query bound; the Source fingerprint hashes the complete 32-byte range rows. Existing manually prepared ranges with mode 0 and zero ABI-15 lanes retain legacy selection behavior and make no motion-envelope completeness claim. ABI 15 changes the range record from 16 to 32 bytes; host callers and Metal libraries must be rebuilt together. This preparation-only change is not a runtime or anatomical contact qualification.
