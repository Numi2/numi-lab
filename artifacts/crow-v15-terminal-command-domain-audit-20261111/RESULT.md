# Corrected terminal command screen versus frozen flight evidence

Correction to the first version of this audit: it compared the raw guidance request directly with the frozen-flight speed range. The journey adapter adds 0.25 minus that request to measured speed, and the frozen law then subtracts 0.15. Thus the effective setpoint in that speed-error expression is the raw request minus 0.10 m/s. The earlier raw-request counts remain in Git history but should not be interpreted as effective setpoints.

In the retained localized-route development run, reconstructing the effective speed setpoint from same-numbered endpoint pose, velocity and logged final-goal error yields 250–798 samples per lane below 0.15 m/s during the observed phase-one approach, out of 275–798 matched samples per lane. Reconstructed per-lane medians range from 0.035 to 0.046 m/s, and 31–188 samples per lane are negative. The frozen-controller evidence covered separate speed commands from 0.15 to 0.85 m/s and specified disturbances on its documented experimental body, not arbitrary combined commands or this perching approach. Below-range setpoints are outside that screen, not automatically unstable.

Telemetry is sampled at accepted control endpoints; source code consumes task state on the following control step, and the reconstruction has not been checked against applied-command instrumentation. These results identify a qualification gap and do not establish the cause of a fall. The flight controller source remains unchanged; terminal-command qualification or a demonstrated feasible approach is necessary before full-sequence claims.
