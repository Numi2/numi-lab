# Correction to knee-target interpretation

The original PLAN and RESULT called the shader values -0.70 and -0.10 radians and inferred that the earlier target must reach the model's -0.10 rad knee limit early. That inference is unsupported and is withdrawn. These values are assigned to `navigationTeacherRequested`, an action request. The physical target path in the same shader applies action availability and selection, history and first-order filtering, a context-dependent residual/carrier, and then for a nonwing joint computes `defaultQ[binding.indices.z] + binding.parameters.x * avianNonWingCommand`, followed by binding limits and the solver's joint-limit clamp. Thus raw request and knee target are different quantities. The actual binding scale, active masks, filtered trajectory and ultimately applied target need to be recorded for these runs before concluding when or whether clamping occurred.

The native model inspection still reports knee position limits of [-0.10, 1.55] rad; the test really did change the action request from -0.70 to -0.10, and the observed impulse, height, parity and failed launch screens remain valid. The label `inrange` is a historical artifact name, not an established physical target range. Neither prior experiment demonstrates a launch.
