# Duplicate reset perturbation requires runtime verification

The candidate turn shader contains two byte-identical consecutive reset perturbation blocks, conditioned on the hierarchical-navigation program flag and difficulty band 10. They request the same deterministic random channels twice for roll, leg joint coordinates and horizontal root velocity. If both execute as written, their effects accumulate subject to joint clamps; the nominal values in either block alone would understate the reset perturbation. The recorded task is the v15 conditional navigation variant with band 10, and the current owner source assigns that variant the hierarchical flag. The actual compiled program flag and this reset branch have not been independently instrumented in the tested binary, so activation and exact magnitudes are not yet established.

For development seeds 20261126 and 20261127 the first recorded q/v states of candidate lanes 6 and 7 differ, as detailed in audit.json. These are observer states after reset processing, not independently captured initial states; seed variation alone is not a designed perturbation distribution or proof of disturbed-start recovery. Do not silently remove either block or reinterpret the archived results. A future controlled ablation should capture the pre-step initial state, compiled program flag and same-seed baseline before changing reset behavior.
