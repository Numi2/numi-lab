# Native cued two-port foraging

`numi crow-env cue-foraging-admission --output NEW_DIRECTORY` runs the native
`metalrobo_crow_cue_foraging_check` instrument. Accepted physical calibration
places two15mm intake volumes0.119327m apart within head reach. One port has
45,000ug finite stock per lifetime; intake is blocked through192 accepted ticks.
A selected-site indicator mesh is visible before initialized lifetime tick32.
Native resource state gates actual mesh visibility; normal native projection,
shading and depth/occlusion own the resulting images. No actor location label,
host physics loop or synthetic RGB overlay is introduced.

All eight admission arms across eight lanes pass. Five lanes have left stock
and three right stock. Left/right native constant-bias policies apply the same
actions to every lane; neither consults hidden food allocation. The matching
side consumes two20,000ug bites and the opposite side none. The native reward
and typed intake outcome agree with4 utility for40,000ug and0 otherwise, with
no reward before the intake delay. Independent integer/raw-array analysis binds
food conservation, masks, finite actor values and14 partition comparisons.

A physical wall occludes them. A paired seed changes four assignments and120
early image lane-frames, while all97 non-image features remain byte exact.
After zero-based tick40 all1251 actor features are byte exact across those
assignments. Reset at48 cannot reveal the cue, reroll food or restart its life.
Neutral chunk1/16 and feeding chunk8/32 preserve native states and streams.
Nine malformed program/resource-owner controls reject. No physical termination
or rejected physics step occurs. Full Release build,29 focused Python tests,
nine existing food controls and six existing live-retinal controls pass.

The first trial calibrated the sites then correctly rejected an unsupported
open-loop retinal execution. Its source/runtime/failure remain retained. The
revised instrument uses bound native policies and fixed phase revisions,
without relaxing the sensor guard, geometry or numerical/capacity bounds.

`manifest.json` maps all selected raw files and variants into content-deduplicated
Git objects. `runtime-recovery.json` selects ten current native roles and exact
learner sources. `restore_runtime.py NEW_DIRECTORY` restores those roles and a
compact reference summary, without another copy of large reference arrays.
`verify_recovery.py` runs the current cue instrument from a fresh Git-restored
runtime, verifies its actual loaded library and compares every native output
against Git reference hashes. All133 non-scene outputs are byte exact. All eight
visual-scene JSON objects, including their fingerprints, match unchanged native
authoring recomputed at the original and restored pack paths. Every reconstructed
visual pack is byte exact. Scene fingerprints intentionally include filesystem
paths; the initial string-normalization comparison failed and is preserved with
its analysis amendment. The completed native replay was reused without rerunning
simulation. Verification removed220 temporary recovery/authoring files (85,583,914
logical bytes) after exact-file validation and an open-handle check. Matching device/OS/dependencies are still required.
Historical executables with absolute build RPATH need an explicit adjacent-library
override and loaded-image audit; the current cue executable uses relative RPATH.
Cleanup receipts retain exact hashes/paths/open-handle checks before removing
raw captures and bulk archive checkout duplicates.

This qualifies a native sensing/intake mechanism, not learned memory or a
biological crow. The cue recipe is not yet an ordinary C API/Swift training
variant, and coupled cue-life restore has not been admitted. Next integrate
that exact recipe, prevent posture/previous-action external-memory confounds,
train sequences spanning cue to choice, and evaluate held-out intact/reset/
absent/swapped-cue conditions. Manipulation, social agents, ecology, measured
biology and production time-to-quality/throughput remain open requirements.
