# Two-segment native toe binding candidate

The retained walking wrapper gates both the old toe drive loop and takeoff state latches on `dispatch.counts.w == 30`, while the present body has 38 generalized velocities. Thus neither path executes on the two-segment body. In an isolated wrapper, retain the old 30-velocity behavior and add a 38-velocity branch. Restore the existing takeoff latch calculation for both topologies; this changes supervisory phase behavior and requires a new takeoff and frozen-flight check. For the new toes, after the route reaches its terminal approach, advance each foot's bounded closure counter only from accepted same-foot contact load; absent load decays it. Map all eight digits to their two position-drive coordinates, with per-interval proximal increments .04 rad rear/.03 rad front, a two-interval front delay, caps 1.15/1.05 rad, and distal targets 0.75 of proximal. Unlike the old branch, the new grip has no 55-second opening timer. These values come from the eight constructed stationary starts but this GPU implementation uses aggregate foot contact, not the prototype's per-foot latch, so equivalence and real perch-specific contact are not assumed. Do not promote the candidate without independent mapping, contact gating, supported release, walk, leg jump, frozen-flight and landing tests. Preserve the previous wrapper, action policies, body and all outcomes.
