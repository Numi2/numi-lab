# Remove contact diagnostic task-state write

Removing the legacy packed-velocity write left all 1200 post-reset `CROW_SUPPORT_SAMPLE` records byte-identical for every same-lane pair on this one development seed. Those formatted records include q, v, policy actions and recorded contact details; equality at the logger’s numeric precision is not a bit-level comparison of every GPU field. All eight first-episode navigation summaries matched, including survival. The retained lane-5 native replay had no recorded reward differences over 1200 frames. This does not compare all lanes’ rewards or decompose reward, and it does not establish that the old write had actually corrupted a reward in this particular run. The source still demonstrated aliasing between a diagnostic field and a field read as mechanical power; the new candidate no longer writes that diagnostic into task state.

The correction is limited to this research shader. The native run used obstacle-disabled development starts, an unqualified flight law and empirical unsteady-force and yaw-moment closures. No gait, aerodynamic, obstacle, supported-landing or held-out qualification follows. A distinct clean-controller gain comparison is prepared; retain both the pre-intervention run and this result.
