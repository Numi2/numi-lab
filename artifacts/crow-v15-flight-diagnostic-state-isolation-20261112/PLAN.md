# Isolate obsolete contact diagnostic from task state

Source audit found that `crow_contact_feedback_publish` writes a packed contact-velocity diagnostic to `airReturnTracking.x` in lanes 2–7 from 4 to 6 seconds. The reward path also reads that field as mechanical power. The diagnostic feedback gains are all zero, so this old write is unnecessary and can corrupt task/reward semantics even if trajectory does not change. Remove that single write in an otherwise identical copy of the current uniform-flight candidate; retain the kernel symbol and all other source. Recompile and compare the same seed and all eight same-lane starts against the immediately preceding candidate. Predict bit-identical accepted q, v and policy actions over the entire first episode; independently report reward/outcome differences and any incomplete samples. A mismatch is a failed isolation prediction to investigate, not proof that disabling the diagnostic is harmless. This is a source-level research correction and must not be called production-qualified or an aerodynamic calibration.
