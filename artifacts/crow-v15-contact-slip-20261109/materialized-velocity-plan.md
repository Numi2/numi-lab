# Experimental task-time articulated body velocity materialization

The task completion pass reads `kCandidateBodies`, whose articulated entries are initialized from positions and orientations with zero velocity. On the reference gait this produces zero left-foot velocity in the task while the time-aligned accepted replay records nonzero foot motion; generalized root velocity matches. The world already has an articulated body velocity materialization kernel. Test an isolated host-library variant that directs this existing kernel to `kCandidateBodies` immediately before native task completion. Keep original solver, GPU source, body, controller, actor, reset, random seeds and contact solver unchanged. This changes task-visible observations/rewards derived from body velocity, so physical trajectories might change and the altered library must not replace the production one without broader tests.

Use the existing read-only contact and diagnostic observer, the prior body-velocity-source shader and the same 350-step, two-lane exposed reference run. Compare physical q/v/body states and report any differences, and measure maximum disagreement between task-time left-foot velocity and the exactly aligned replay body velocity. An adequate instrumentation result requires finite, nonzero foot velocities in moving samples, max error <=1e-5 m/s, no simulator failures and no physical failure. This is not a gait, navigation or biological qualification; preserve both runs and report behavior changes rather than forcing parity.
