# Rear-toe release command timing

The retained matched-body traces capture the actual rear-toe proximal motor targets and contact normals. In 40 complete stance runs for the unloaded-release arm, no target below -0.001 rad was observed by the last front-toe contact. In the loaded-release arm, 24/40 had no such target by front-toe release and the other 16 had a captured command only 1.25–2.5 ms before the last front-toe contact; those 16 targets were sampled within that same 20 ms control interval and cannot establish that the command preceded the contact. All 40 loaded-release runs still had rear-toe contact after the front group. Target capture is not actual joint movement, and toe mapping, thresholding and run segmentation remain uncertain. The support flags in audit.json are post-step, not pre-command causal gates.

This supports examining command lead time, rather than merely increasing release amplitude. It does not establish why the physical toe remains in contact, nor validate any proposed change. The 0.5 s carrier in prior toe-phase.py and load-phase.py is the leg carrier; the rear-toe drive additionally has a 0.50-rad phase shift, so those phase bins must not be interpreted as the exact toe-command phase. Raw motor target and contact data, direct joins, and per-event values are retained in the parent study and audit.json.
