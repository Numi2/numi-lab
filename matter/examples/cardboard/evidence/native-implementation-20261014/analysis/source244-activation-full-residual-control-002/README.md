Source244-002: opt-in full-residual mortar activation and scene evidence

This overlay is based on immutable source241-004. The legacy path remains the default: activation selector and sparse-private settings are cleared for the setup transaction. The opt-in --full-contact-activation-residual-armijo mode is allowed only with native sparse-free-body parity and diagnostic-state output. It binds the activation setup to control 1199 (the fixture base is 1200), selects the existing full-contact residual Armijo path for that setup transaction, and requires the runtime selected-path marker. A zero control base is rejected before subtraction; the CPU contract checks 1200 to 1199 and base-zero rejection.

Each dense/sparse setup writes exact host scene input bytes, the kinematic-target bytes passed by the runner, MetalWorldResult.finalSceneBodies if the completed run published them, runner scene state after the call, and returned q/v vectors. It also binds accepted-step counters and Matter before/after snapshots. When the MetalWorld result has no published scene vector, metadata says unknown_no_published_scene_readback; it never treats the runner's unchanged host state as proof of device-buffer rollback. The public StepResult API does not expose the underlying MTLBuffer, so the sidecar is an exact published host readback when available, not a raw Metal-buffer dump. If the Matter after snapshot is unavailable, its file/hash remain null and the status is marked unavailable while the scene evidence is still emitted.

The production shipping probe continues to request the existing full-contact selector for its authored shipping schedule (NM_FEM_FULL_CONTACT_RESIDUAL_ARMIJO_ROOT=all); this checker option does not gate or remove that path. No solver kernel, physical operator, acceptance criterion, or tolerance changes. This is instrumentation plus an explicit fixture selector, not a physical qualification. No GPU test has been run for this overlay.
