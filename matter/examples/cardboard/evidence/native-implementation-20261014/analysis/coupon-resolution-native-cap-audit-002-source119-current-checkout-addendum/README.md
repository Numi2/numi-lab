## Bounded graph-Schwarz scaling

The target combined case is `N=20,682`, `T=89,088`, `E=2`, with 324 authored fixed nodes and 20,358 free nodes in the audited mesh-count table. Current source119 blocks it before layout construction: compiler admission is at most 4,096 nodes and 32,768 tets, validation repeats these caps, and `buildRegionalGraphSchwarzLayout` uses those defaults. The target is contact-free; contact capacities are not a gate for selector 5.

The current graph layout stores two dense matrices per environment (factor storage plus original matrix for one refinement pass), pivots, patch corrections, validity and O(N+patch-node) metadata. Its full-node coverage at 128 equal-size dense patches would require about 468,703,636 bytes (446.99 MiB), including 1,307,556 bytes of metadata, which is 368,040,340 bytes above the 96 MiB cap. Raising the node or byte cap alone therefore does not make the current dense representation suitable.

A bounded candidate worth prototyping is a hybrid right preconditioner, not a claim of qualification: retain the current 32-mode coarse RAP; select at most 128 deterministic 64-node graph patches; build exact production-A principal patch blocks; use the existing exact 3x3 nodal block inverse (with its established diagonal fallback) only for free nodes outside graph coverage; and keep constrained nodes zero. The two-environment graph arenas would be about 76,583,508 bytes (73.04 MiB), leaving 24,079,788 bytes under the existing 96 MiB graph-layout bound. The selector-3/4 block-inverse buffer adds 1,985,472 bytes for two environments; the regional authored P/effective P/AP/coarse estimate at M=32 is 52,983,840 bytes. These are arithmetic arena estimates, not an observed total resident or peak. `nodeCoverage` is shared across environments in the existing layout, so the fallback must be validated for every environment's actual free/fixed mask.

This candidate only becomes safe if admission and kernels change together: the builder needs a deterministic partial-coverage mode and an explicit descriptor/hash; host and shader coverage gates must require a valid local patch OR valid block/diagonal fallback for each free node; the graph apply kernel must use block inverse on the uncovered residual `r-APc`, with no double application on covered nodes; factor-invalid covered patches must fail closed; full production A/RHS/certificates remain unchanged. Runtime/compiler/validation still need bounded N/T admission based on index arithmetic, `maxBufferLength`, and measured resident memory. A native parity fixture must compare full-node preconditioned actions and accepted solver certificates against a dense/bounded reference, exercise uncovered nodes, singular local blocks and rollback, then run the planned mesh/time triplets. Do not promote the estimate to a supported capacity or relax physics/tolerances based on it.

### Scratch and execution bounds

A 64-node patch has 192 scalar DOFs. The graph LU kernel's largest search arrays are 3×256 32-bit values (3,072 bytes) per threadgroup. The graph solve declares three fixed 768-float threadgroup arrays (9,216 bytes total) even when the active patch is only 192 scalar DOFs. With 128 patches and 2 environments, the estimated dense patch-factor work is approximately 604 million multiply-add updates (about 1.21 GFLOP counting multiply and subtract separately) per factorization sweep, apart from operator assembly and refinement. These threadgroup and operation estimates do not predict GPU time; selector-5 graph kernels are run each relevant Newton/restart preparation and need native timing.

The artifact `graph-scaling-estimate.json` reproduces the arithmetic from source119's checked layout formula. The 27-row mesh preflight table remains in audit 001 and is not duplicated or altered here.
