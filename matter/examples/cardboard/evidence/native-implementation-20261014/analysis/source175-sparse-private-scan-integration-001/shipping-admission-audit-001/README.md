# Nominal shipping admission audit

This is a CPU-only source and arithmetic audit for the supplied nominal topology: one environment, 528,444 FEM nodes, 1,477,728 tetrahedra, 260,835 cohesive faces, 1,054,876 surface faces, and 6,335,568 canonical contact pairs. It does not instantiate a Matter world, dispatch Metal, or claim an assembled physical result. The reusable calculator, compiler-derived `sizeof` probe, and result are in this directory and the package's `validation/` directory.

The first explicit full-contact Armijo scope rejection is `femNodeCount > 8192` (`runtime.mm:10918–10920`, current source175 candidate). The full-contact scope calls the capsule/box scope at `runtime.mm:11141–11146`; that scope checks this node cap before its tetrahedron and arena checks. The target exceeds it by 520,252 nodes. The separate diagnostic `femNewtonTraceScope` cap is 4,096 (`runtime.mm:10649–10651`) but is not the direct full-contact selector's first check.

Further gates remain even if the node scope cap changes:

- Full-contact scope requires no more than 32,768 tetrahedra (`runtime.mm:10921–10924`); target is 1,477,728. The full-contact deformable scratch `supportedCounts` independently requires nodes <=16,384, tetrahedra <=32,768, and deformable contact capacity <=131,072 (`runtime.mm:6857–6862`). Its runtime estimate also has a 128 MiB limit (`runtime.mm:6843–6845`).
- At 260,835 cohesive faces, the non-tiled private path exceeds the 4,096-face limit. The tiled path uses 96-byte `NMCohesiveFaceVectorGPU` values and an 8 MiB page: floor(8,388,608/96)=87,381 faces/page, 8,388,576 bytes/page, three pages (`runtime.mm:6624–6674`, `11147–11160`). This page calculation fits; it does not bypass the node/tetrahedron checks or certify the material model.
- Sparse private-pair scanning at one environment, 6,335,568 pairs, and candidate capacity 65,536 uses 36,189,188 bytes: samples 10,485,760 + pair-slot map 25,342,272 + candidate IDs 262,144 + count sentinel 16 + block offsets 98,996. The existing 36 MiB limit is 37,748,736 bytes, leaving 1,559,548 bytes. At two environments, checked total is 72,378,360 bytes and admission rejects it. The scan preserves canonical pair order and retains the existing overflow failure; it is only scratch for private candidate evaluation.

The source-bound `sizeof` probe reports node state 80 B, tetrahedron 96 B, cohesive face 384 B, cohesive face force 96 B, contact-pair record 16 B, contact sample 160 B, surface primitive 64 B, deformable candidate 16 B, deformable contact 432 B, incidence range 16 B, and indirect dispatch 16 B. At the nominal dimensions, one node-state array is 42,275,520 B; one tetrahedron array 141,861,888 B; one cohesive-face array 100,160,640 B; and one contact-pair topology array 101,369,088 B. Accepted/candidate pairs of these arrays, where both are materialized, double the respective per-array byte count. A dense sample array would be 1,013,690,880 B; the sparse candidate sample array is 10,485,760 B.

The modeled deformable-contact scratch expression from `runtime.mm:6865–6878` was evaluated at capacity 131,072 and the supplied face count as primitive count. With no surface-scratch alias, primitives + four BVH bound arrays + four sort key/index arrays total 218,607,808 B; contact-capacity arrays add 62,914,560 B; node incidence ranges add 8,455,104 B; small count/dispatch arenas add 32 B. Total 289,977,504 B exceeds the existing 128 MiB budget. If the surface arrays are exactly aliased to already-resident production scratch, modeled incremental amount is 71,369,696 B and fits that local budget. This is conditional arithmetic only: the actual topology-derived primitive count, alias pointer identity, allocations, and total process peak require runtime evidence.

The prior native allocation report is for a different 453,378-node mesh with zero cohesive faces. It measured 10,467,551,760 B runtime resident and 10,504,568,832 B Metal current allocation, while the recommended working set was 19,069,665,280 B. That report labels the recommendation advisory and `qualification_allowed=false`; its measurement is not reused as the target's memory peak.

The same preflight's static lower-bound categories, scaled arithmetically to the target, are `N*80 + T*96 + (2N)*528 = 742,174,272 B` for E=1. The 528 B/unknown factor is derived from the prior lower-bound FGMRES entry (478,767,168 B for 2*453,378 unknowns). This is explicitly a scaled lower bound, not a complete arena inventory or peak forecast; it omits many runtime/device/host/contact/checkpoint/compiler allocations. Therefore it cannot establish the 16 GiB shipping ceiling.
