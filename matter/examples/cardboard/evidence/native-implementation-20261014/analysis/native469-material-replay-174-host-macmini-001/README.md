# Native469 material replay host package (macmini)

This package builds and prepares a diagnostic replay against the retained source469 Newton capture. The replay evaluates captured constitutive points and derivative directions; it is not a physical transaction, full-coupon validation, calibration, or material qualification.

The package is host-bound to `/Users/n/cardboard-implementation-20261014-host-macmini`. It uses immutable source173 (`source-checkpoint-warm-breakdown-173`) and its successful build `build-source173-001`. The original checker was authored for source169; the host wrapper applies only the two-line source-name rebinding recorded in `patch/source173-binding-rebase.patch`. The diagnostic Metal shader and common material helper match byte-for-byte in source169, source157, and source173; the 13-file equivalence table is retained in `validation/source-material-include-equivalence.json`.

The origin inputs are the exact retained source469 capture and failed full-run artifacts, plus the separately bound MP fallback report/arrays and selected reference export. All eight input hashes passed CPU admission. The default `validation/run_guarded_source469_v2.py` performs hash checks and CPU-only admission. It requires explicit `--execute` to launch Metal work. Its preflight's `launch_allowed` is only a point-in-time check; execute rechecks active Numi Matter/sparse-scan/source469 workers, the source173 worker lock, all hashes, a fresh output path, and free disk. During explicit execution it samples process-group RSS against a 16 GiB ceiling, preserves at least 2 GiB free disk, and caps runtime at 7,200 seconds by default (14,400 maximum). RSS is sampled protection, not an OS memory reservation.

No native replay was dispatched by this package preparation. The Objective-C++/Metal build completed and CPU admission passed. `build_host174.py` exited 1 only while serializing its final receipt because the rebasing patch was present at the package root instead of the declared `patch/` directory. The four recorded subprocess steps all returned successfully before that finalization error; their command records, empty stdout/stderr logs, AIR, metallib, object, and executable are hash-bound. `finalize_host174.py` verified those already-created outputs without rebuilding or overwriting them and records the original script exit honestly. The original exact source174 wrapper, initial wrong-path source hash preflight, and v1 preflight that lacked launch-availability reporting are retained as superseded evidence.

At the last v2 preflight, 113,815,646,208 bytes were free (113.8 decimal GB, about 106 GiB), all hashes and CPU admission passed, and no matching worker/locked source173 lease was observed. That availability reading is time-specific. The CPU admission covered 1,920 captured centers, 17,280 nine-direction center inputs, 9,600 captured center/side states, 5,940 epsilon rows, 34 repeatability rows, and 17 MP roots. Repeatability is not an accuracy floor; the diagnostic does not close all-direction FD noise, all physical conditions, assembly validation, mesh convergence, or full-cycle qualification.
