# Deterministic private deformable narrowphase status selection — native checker candidate

This isolated source109 overlay carries the previously reviewed per-candidate private narrowphase status scratch and ascending-slot reducer, and extends the existing `numi-matter-cardboard-contact-ccd-native-check` executable to invoke both production Metal kernels. The source109 CMake target and CTest registration already exist, so this overlay does not change CMake.

The native check has two focused device checks. First, it invokes `nm_contact_narrowphase_deformable` with selector 1, preloads all six private status records with stale failures, and dispatches two environments with one inactive counted candidate and one empty active prefix. It requires the production narrowphase to clear every per-slot record while leaving environment statuses untouched. Second, it calls `nm_contact_reduce_deformable_narrowphase_failures` with four environments and fixed per-slot status tuples: multiple private failures where the lowest slot must win; an earlier environment failure that must remain byte-identical; an empty active prefix with stale failure data; and a healthy active prefix with a stale failure only in its tail. It also verifies the selected tuple and that recordFailure leaves completed-microstep, FGMRES, contact, and event counters unchanged.

The native reducer test seeds fixed candidate-status records directly; the narrowphase device check verifies clearing on the production producer path but does not exercise a geometric failure branch in that producer. The source-bound CPU contracts check that all seven narrowphase failure sites route through the per-slot writer. This is a production-reducer kernel regression, not a full contact-physics qualification.

Selection is deterministic by lowest candidate slot for a fixed upstream candidate sequence. It does not establish a geometry-independent candidate-pair order if candidate enumeration changes. Existing ordinary narrowphase passes selector 0 and preserves its prior environment first-writer behavior. Contact geometry, physical operator, acceptance, tolerance, and capacity are unchanged.

The extra private scratch is `environmentCount * deformableContactCapacity * sizeof(NMMatterStatusGPU)`. The unchanged ABI record is 48 bytes; with the existing maxima of four environments and 131,072 slots per environment, the maximum extra arena is 25,165,824 bytes (24 MiB). Allocation uses the checked `privateScratch` path and is included in `residentBytes`. The native checker itself allocates only small fixed test buffers.

`contract_test.py` passes 14 CPU source/contract checks, and `overlay.patch` passes a source109 patch dry-run. Metal compilation and native device execution have not been run for this overlay; root should run the existing target after integrating it.
