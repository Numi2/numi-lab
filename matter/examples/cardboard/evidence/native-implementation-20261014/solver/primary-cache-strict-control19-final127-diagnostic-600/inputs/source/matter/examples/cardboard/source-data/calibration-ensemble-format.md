# Whole-fixture calibration ensemble

`matter/tools/cardboard_calibration_ensemble.py` compares complete native forward histories with published fixture intervals. It does not run Matter, change constitutive parameters, interpolate a fitted law, or assign probability distributions. The output retains every supplied parameter set that satisfies all required calibration-fixture intervals and reports one-factor sensitivity ranges. These ranges are descriptive, not confidence intervals. A finite grid can show that multiple supplied candidates remain feasible; one surviving grid value does not prove global identification. Validation/holdout sensitivity is reported separately and never changes feasible sets.

Run it with:

```sh
python3 matter/tools/cardboard_calibration_ensemble.py PLAN.json \
  --catalog matter/examples/cardboard/source-data/catalog.json \
  --data-dir matter/examples/cardboard/source-data \
  --output RESULT.json
```

The input plan schema is `numi.cardboard.calibration_ensemble.v1`. Bind it to the exact catalog bytes with `source_data_catalog_sha256`. Each condition names one catalog `dataset_id`, its direct `source_id`, catalog dataset SHA-256, publisher original or retained text-extract SHA-256, catalog SHA-256, a unique `specimen_id`, a condition ID, a role (`calibration`, `validation`, or `holdout`), and an exact whole-fixture `selector`. Selectors use the complete grouping keys declared in `CONDITION_KEYS` in the tool. Individual rows, point ranges, and reuse of a selected fixture under another split are rejected.

For the Johnson–Popil pin records, `source_ids` identify only the artifact whose pixels were digitized: the 2016 author presentation. The 2015 article is separately named by `protocol_source_id` and supplies method context such as specimen size and loading rate. The article's Figures 4–5 were not digitized into these CSVs, and their value-by-value identity with presentation slides 15–16 is unresolved. The package validator rejects adding the article to the pin dataset's direct `source_ids`; the article and presentation must not be counted as two independent conditions. The hash-bound engineering pin profile is a model input, not published fixture geometry.

The slide-15 traces are illustrative source-series curves with no individual specimen IDs. Keep their two `(series_id, defect_id)` selectors as separate whole conditions; do not infer replicate identities or combine the article figures with the presentation data. The low-adhesion trace exposes a visible curve peak, but the plotted displacement axis omits its zero/contact origin. Therefore a pin-mode prediction must not be shifted freely on the displacement axis to align stiffness or work. Any stiffness/work comparison needs a documented, source-compatible window definition; otherwise those metrics stay unavailable. The higher-response trace has an obscured later branch and cannot establish the specimen's global peak. Neither curve reports a condition-level failure locus. Keep `failure_locus` unavailable rather than predicting a native damage category as if it were observed evidence.

For the low-adhesion white-glue trace only, a source-compatible *visible-curve descriptor* can use a threshold window. Add `source_window: {"start_load_N": 30, "end": "first_post_peak_return_to_start_load"}` to the metric. This begins at the first plotted 30 N loading point, finds the visible peak, and closes at the first post-peak return to 30 N. Source endpoints are linearly interpolated where needed; digitization bounds at interpolated endpoints conservatively use the larger adjacent readout uncertainty. The window removes sensitivity to the unknown absolute displacement origin. It does not recover omitted portions of the physical test or turn the window area into the paper's separately reported pin-work quantity. The 30 N threshold is a plot-window choice tied to the visible series, not a new experimental force threshold.

Native pin histories retain the instrument's raw accepted sample fields: `phase`, boolean `accepted`, `acceptedStep`, `elapsedS`, `commandedRelativeSpeedMPerS`, `relativeOpeningM`, and `instrumentLoadMagnitudeN`. The `samples` array may also retain rejected attempts, but windowed metrics use only samples with `accepted: true`; certificates must still bind the complete history and the completed protocol. For the pin trace, use `native_window: {"phase": "relative_opening", "start_load_N": 30, "end": "first_post_peak_return_to_start_load", "required_phases": ["platen_approach", "relative_opening", "platen_withdrawal", "released_hold"]}`. This requires all four completed phase names and derives metrics only from the accepted `relative_opening` branch.

The solver emits `relativeOpeningM` in metres while the plotted source ordinate is in N/mm coordinates. Preserve that raw field and unit in the hashed history; for an N/mm secant/work descriptor, declare `prediction_x_unit: "m"`, `x_unit: "mm"`, and `prediction_x_scale: 1000`. The metric kind may be `peak_branch_secant` for the source and `prediction_kind: "secant"` for the native loading secant to its windowed peak. For curve area, use `kind: "work"` with `unit: "N*mm"`; interpret the output only as area under this selected visible curve interval. A work comparison remains excluded if the selected source specification relies on the paper's unresolved pin-work unit rather than the plotted-trace integral.

Metric definitions use published source columns and explicit units. Numeric metrics support `peak`, full-window `secant`, and trapezoid `work`; a categorical `category` metric can represent a source-reported failure locus. For analogue failure categories, the plan must give an explicit list of allowed labels for that source category. The source uncertainty columns are used where the package records digitization bounds. Secant stiffness is derived from the first and last points and is labeled as such. Work is integrated only across the full trace present in the source CSV; it is not extrapolated beyond the plotted window. Every required metric must be available. A missing failure-locus observation blocks a complete fixture fit instead of being inferred from a curve.

Each condition also needs a transfer declaration. `same_grade` requires matching explicit source and target grade IDs. `bounded_analogue` requires both grade IDs, a written rationale, and nonzero positive scale intervals for each numeric metric. The tool applies those intervals to the source/digitization bounds. This is an explicitly declared transfer scenario; it does not establish grade equivalence. Units must match exactly. In particular, Johnson/Popil's pin-adhesion summary work remains excluded while the published N-m label conflicts with the integral of its plotted N-by-mm curve.

Candidates are explicit JSON objects with unique IDs, a canonical SHA-256 over the candidate object excluding the hash field, and role `fit_candidate`, `unbonded_control`, or `tied_control`. A fit candidate supplies named values, units, parameter families, and an explicit `fit` flag. Its `origin` must say `user_supplied` or `sensitivity_grid`. The program does not invent candidate values or select a best fit. Unbonded and perfectly tied controls have explicit control definitions and cannot carry fit parameters; their results remain in a separate output section.

For each candidate and each whole fixture condition, `native_histories` references a JSON history and execution certificate using paths relative to the plan. Both files are SHA-bound in the plan record. The certificate binds the candidate, specimen, condition, source catalog/dataset/publisher hashes, complete protocol step counts, the history bytes, and hashes for four retained artifacts: `native_input_manifest`, `native_executable`, `solver_source`, and `run_receipt`. The manifest binds the exact candidate parameters and source/specimen identity. The receipt must identify `numi_matter_native_fem`, and the certificate must identify `native_forward_prediction`; an explicitly CPU/oracle-labelled run is rejected. The history supplies all accepted samples, named quantities, and their units. Every candidate must have a complete history for every listed condition.

An admitted certificate is a provenance and integrity record, not a cryptographic attestation that the named executable ran on particular hardware. Preserve the source run receipt and build/source artifacts in a trusted run archive and review them before admission. A self-hashed JSON record alone cannot establish that a result was produced by the claimed native solver. The CPU tests create temporary contract fixtures to exercise rejection and interval logic; those fixtures are explicitly test-only and are not evidence or eligible native histories.

`heldout_predictive_sensitivity_ranges` reports paired one-factor candidate contrasts for validation and holdout conditions. These ranges are descriptive only: held-out response never admits or rejects a calibration candidate and never narrows `feasible_parameter_sets`.

## Current evidence boundary

The checked-in source-data catalog has analogue observations for pin-force traces, ECT, box compression, scored bending, and external hot-melt joints, plus source-law and equation checks. Those sources do not provide a matched `literature2009` corrugated-board specimen series with force history and failure locus for identifying mixed-mode starch-interface parameters. The pin summary work unit remains unresolved; pin traces remain analogue holdouts, not calibration rows. Several catalog sources have no retained original/text SHA-256. Those conditions cannot be used as calibrated evidence until their provenance and units are resolved.

The available pin-force plot can support a whole-curve analogue comparison for a selected defect/series when all source hashes and transfer bounds are supplied. It cannot calibrate the current grade's GI/GII, mixed-mode interaction, or failure locus. Likewise, the hot-melt seam source is a different adhesive system from the board's internal starch bonds. Keep that comparison as a bounded external analogue or a limiting control; do not transfer it as a fitted starch law.

In the current package, no matched native source condition has been admitted for cohesive calibration. The Haj-Ali table contributes only reported yield anchors, not raw stress-strain histories, and its current catalog entry lacks a retained source-asset/text hash required by this tool. The tool therefore cannot produce a calibrated cohesive parameter set from the existing package. A valid future package needs hash-bound source specimens, full fixture protocols, units, digitization bounds, condition-level outcomes where available, and genuinely source-bound native forward runs. If GI/GII remain unidentifiable after those comparisons, report the entire feasible candidate set and sensitivity ranges; do not return a guessed default or a confidence interval.
