The existing Metal stand solver remains the only contact-force owner. The candidate does not truncate source weights or read skin geometry back to the CPU per step.

The actual candidate runs are `human-support-hybrid-basisz-64-001` and `human-support-hybrid-basisz-1120-001`. ## Timestep probes

`human-dt2-transaction-64-001` completed 64 steps at 2 ms (0.128 s simulated) with the integrated forced-rejection proof enabled. It reported unchanged body q/v/root/Myo, unchanged circulation and clock, unchanged respiration/Brain history, byte-identical retry against uninterrupted replay, and a same-command-buffer case with accepted prefix 2, rejected step 2, and inert suffix 1. Full-skin audit reported zero vertices more than 1 mm below the bed, zero non-finite skin vertices, and maximum functional-volume relative error `6.87532804022e-7`. This is a short transaction/refinement result, not a six-second breathing qualification.

That 2 ms probe used native binary SHA-256 `1c3edd7caef167de8ddcd62ca6ad14559fdae3d3a90f36013780d969bb2e29c4`; its app source was `56a2713bcd12d0c406234cec07ae006f2af2cdd9e1d06cca6462bb0a57205e6f` (the temporary app admission allowed up to 4 ms, but the run itself used 2 ms). The successful run’s `invocation.json` preserves all payload paths and environment flags.

The retained 4 ms experiments are failures, not accepted intervals. `human-dt4-transaction-64-001` was rejected by the respiratory parameter loader before simulation. For `human-dt4-transaction-64-002`, the remote loader admission was temporarily widened only to allow a 4 ms diagnostic; no contact or equilibrium tolerance was relaxed. The scene then failed its source-constrained static equilibrium before any physical step: status `success`, normalized residual `1.078475` unchanged from initial, maximum/root acceleration `10.756893 m/s^2`, support force `279.526392 N`, and one active static support. The existing admission requires acceleration residual times the actual physical timestep to be at most `0.025`; at 4 ms the measured product is `0.0430276`. The 4 ms cap was not promoted. The local parameter admission is restored to `dt <= 0.0021f`, and the resting physical timestep cap is 2 ms; legacy calls retain their 1 ms cap.

The temporary 4 ms diagnostic used app source SHA-256 `56a2713bcd12d0c406234cec07ae006f2af2cdd9e1d06cca6462bb0a57205e6f`, a remote-only respiratory parameter header SHA-256 `d5708c9c739af88cdcb5f94fac679ef5c0f33d1909ce3d336542a6a0cfa4f76a` with only the admission literal widened, and native binary SHA-256 `c7a6441affdc422ccdaeb53a49bd94aa73ab32ca49acdeb2152d3cd2b5bb22ed`. The local source was restored after the diagnostic; its exact failed command and artifacts remain in the run receipt.

Using a separate, smaller timestep only for static initialization would not preserve the runtime source law: the reference-safe static-force evaluator and the runtime owner both use `max(solref.x, 2 * timestep)` for source compliance. The current 4 ms failure is therefore preserved rather than bypassed with a different force law or hidden support.
