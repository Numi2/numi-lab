# Numi Human Metal performance audit and route to at least 0.1x

Audit date: 2026-10-20. Status: source and retained-profile audit; optimization plan, not a measured speedup. All source inspection and evidence processing ran on SSH numi. No simulation, visual verification, physics modification, or new benchmark ran for this audit.

## Result

The current full-contact short replay advances 0.000500000024 simulated seconds in 52.458609958 wall seconds: **0.0000095313x**. Its four roots all accepted, but this covers only 0.5 ms of initial mechanics. It does not establish settled throughput or integrated physiology qualification. Reaching 0.1x from this measurement needs approximately **10,492x**, not a small threadgroup adjustment. Earlier faster scenes are different workloads and cannot qualify the current tissue-contact scene.

The strongest source findings are statically encoded iterative tails, a quadratic contact-incidence path, serial surface sorting, and mixed-field work scheduled across the mechanical mesh. Their individual shares are not yet measured. The next changes should remove unnecessary work in the existing solver, then establish the largest accurate stable timestep. A full Metal 4 migration is unnecessary to begin.

## Apple guidance applied

1. Profile the actual limiter, distribute sufficient work, and reduce small serialized dispatches and timeline gaps. This directly motivates the work-graph and contact audit below. [Scale compute workloads across Apple GPUs](https://developer.apple.com/videos/play/wwdc2022/10159/).
2. Generate dispatch arguments on the GPU when they depend on GPU results, avoiding a host readback/wait decision. Use the existing indirect-dispatch support for active solver work. [Specifying drawing and dispatch arguments indirectly](https://developer.apple.com/documentation/metal/specifying-drawing-and-dispatch-arguments-indirectly).
3. Measure launch starvation, occupancy, register/cache pressure, ALU and memory limiters separately. Low occupancy alone is not a diagnosis. The retained timestamps do not provide these counters. [Discover new Metal profiling tools for M3 and A17 Pro](https://developer.apple.com/videos/play/tech-talks/111374/).
4. Choose threadgroup sizes from pipeline execution width, resource use and measured behavior. Do not blindly maximize threadgroup size. [Calculating threadgroup and grid sizes](https://developer.apple.com/documentation/metal/calculating-threadgroup-and-grid-sizes).
5. Select resource storage by access: shared for CPU/GPU interchange, private for GPU-only intermediates. The runtime already uses private persistent buffers; unified memory does not justify duplicate state. [Choosing a resource storage mode for Apple GPUs](https://developer.apple.com/documentation/metal/choosing-a-resource-storage-mode-for-apple-gpus).
6. Reduce shader resource pressure and use specialization to remove immutable unused branches. Lower precision is appropriate only where the algorithm's precision requirements permit it. This audit does not recommend changing physical certification to half precision or enabling global relaxed math. [Learn performance best practices for Metal shaders](https://developer.apple.com/videos/play/tech-talks/111373/), [Optimize GPU renderers with Metal](https://developer.apple.com/videos/play/wwdc2023/10127/).
7. Keep submissions large enough to avoid overhead without starving the GPU. This is a later latency optimization after the present multi-second work is reduced. [Metal Best Practices Guide: Command Buffers](https://developer.apple.com/library/archive/documentation/3DDrawing/Conceptual/MTLBestPracticesGuide/CommandBuffers.html) is archived guidance; the current compute and profiling sources above take precedence.

## Source audit findings

**1. Full iterative budgets are encoded even when individual kernels early-return.** matter/src/runtime.mm:19816 encodes every Newton iteration; :24450 every restart; :24565 every Arnoldi column. At :10925 and :12342, exponent 2 gives four microticks. Run 060 records 6,144 orthogonalization launches, exactly 4 x 24 x 64, plus 18,432 field-smoothing and 24,676 launches each of the mixed element/node operators in one root. The GPU convergence checks at matter/src/metal/fgmres.metalinc:1687, :5440 and :6139 skip shader work but do not remove those dispatches. Some kernels also perform required zero writes before returning, so suppressing everything after a convergence flag would be incorrect. runtime.mm:10737 already supports indirect dispatch; extend that owner rather than add CPU convergence polling. Real work versus inactive tail cost remains unmeasured. The failed budget-16 speed experiment prevents claiming this is the sole dominant cost.

**2. Default deformable contact incidence scales as nodes x active contacts.** matter/src/metal/contact.metalinc:6920 and :6975 scan every active contact for each node, twice. The scan at :6948 additionally prefixes node ranges on lane 0. runtime.mm:3681 makes the sorted alternative opt-in through NM_CONTACT_NODE_INCIDENCE_SORT=1; the retained invocations do not set it. The existing alternative preserves stable contact-slot/corner ordering and history identity (:6776), but uses a capacity-padded bitonic sort with log-squared passes and barriers (runtime.mm:10872). It must be measured, not assumed faster. First compare it unchanged. If padded capacity dominates, compact six actual support corners and use deterministic tiled sort/scan within the same contact owner. Never cap away valid contacts to improve timing.

**3. Surface sorting exposes little parallelism for one human.** nm_contact_sort_surface_primitives uses one 32-thread group per environment and loops over all primitives (contact.metalinc:1505-1617; runtime.mm:18610). This scene has 21,358 canonical surface faces. A single environment cannot fill a 12-core GPU through that kernel. Count/sort/BVH/narrowphase timings and active face counts must decide whether to implement a tiled stable radix sort, conservative BVH refit, or both. Existing Armijo surface-cache checks must remain valid; topology mutation or failed cache validation must rebuild. Do not assume the present BVH search is a brute-force all-pairs search; it already has a BVH.

**4. Mixed fields occupy a mesh-wide path even for non-transport objects.** runtime.mm:24621-24703 schedules three field smoothing passes over the FEM nodes/elements per Arnoldi column. mixed_fem.metalinc:286 already bypasses element evaluation when mixedMaterialCount is zero and rejects non-multiphysics objects, but launches and field storage/reductions remain. The node kernel still produces boundary-consistent results. First record the cooked counts and active field rows for this exact scene; if no transport fields exist, omit only the provably empty field subgraph with equivalent zero/boundary results. Otherwise compact the actual transport subset. Do not disable vascular or respiratory coupling; those owners are distinct from these packed mixed-field rows.

**5. Global Krylov reduction runs on one threadgroup per environment.** fgmres.metalinc:6118-6207 uses 256 lanes to scan mechanical, field and other blocks, then repeatedly scans them for each basis projection. It uses compensated sums and reorthogonalization; preserve their numerical purpose. The 060 point samples range from 1.625 to 1,419.625 microseconds, with a 1.833 microsecond median, so inactive samples are not representative of expensive active reductions. If active reduction time is significant after removing empty work, distribute partial reductions across threadgroups and retain a deterministic final reduction/small Hessenberg solve. Extra launches can lose on small systems; retain the existing small-system path.

**6. Preconditioning and timestep are part of the performance problem.** The Human scene selects mode 0 despite an existing coupled FEM tangent-block option (apps/numilab_human_myosim_visual_probe.mm:19180-19191). Exact tangent caching is already enabled. Evaluate existing preconditioners against total accepted-step time, including setup, not iteration count alone. Thin skin/fat elements, pressure preload, contact and attachment stiffness may limit conditioning and usable dt; no retained profile isolates their shares. Diagnose per-object residual/correction and minimum-altitude distributions before changing mesh resolution or materials. No stiffness softening, mass inflation, hidden constraints, or skipped contact is an acceptable speed shortcut.

**7. The timestamps are a partial instrument and alter the workload.** runtime.mm:10591-10620 ends and recreates compute encoders for selected samples; metal_encoder_timing.hpp:65 uses a 4,096-sample capacity, and :177 attaches encoder-boundary timestamps. Run 060 sampled every 512th selected dispatch, not every kernel. Its sampled mixed-element median is 23 us, node operator 2.708 us, and field smoother 1.958 us; multiplying those samples by counts is not a validated total. Stage-labelled encoders may cover more work than the label implies. Use a complete non-overlapping stage ledger and compare profiling-on/off wall time before attributing speedups. Full Xcode profiling is currently unavailable on this host; existing timestamp/dispatch instruments can support the first changes without blocking on installation.

**Already sound; retain:** GPU-private persistent buffers (runtime.mm:1637-1651), prebuilt pipeline tables, cached tangents, existing indirect dispatch, stable contact identities, compact accepted-state publication, and the shared Human/Brain/continuum transaction. runtime.mm:1699 waits for initial asset upload, not each physics iteration. Human state readback is suppressed between requested observation endpoints (apps/numilab_human_myosim_visual_probe.mm:8886). NumiBrain is encoded through its owner (apps/NumiHumanBrainController.hpp:684), and body/Brain advance once per frame while continuum/circuit subcycle (human_resting_runtime.hpp:434). Preserve these boundaries.

**Later opportunities:** runtime.mm:10608 fixes generic threadgroups at at most 256 rather than per-kernel measured choices; :3068 performs a string-key pipeline lookup per launch; repeated bindings and broad buffer barriers can add overhead. Benchmark 64/128/256 threads where legal, cache typed pipeline handles, specialize immutable capabilities, fuse compatible pointwise operations, and tighten hazards only after dependency review. Do not remove required barriers or fuse across an unsupported grid-wide synchronization boundary. No current profile justifies prioritizing half precision, render cosmetics, new frameworks, or a wholesale Metal 4 rewrite.

## Ordered implementation and decision plan

1. **Complete attribution on the exact 062 scene.** Add compact counters/timestamps to the existing instruments for CPU encoding, command GPU span, surface build/sort/BVH, narrowphase/CCD, contact incidence, constitutive/tangent builds, active linear work, inactive tails, certification/rollback and observer work. Record actual versus encoded Newton/Krylov counts, active/capacity contacts and fields, private bytes, peak resident memory and swap. Use one root, then the same four-root prefix; sample a complete disjoint stage partition. Calibrate profiling overhead against an uninstrumented run. Preregister each paired trial before execution per the existing scientific workflow. This audit itself is inspection, not a trial.
2. **Take existing low-risk options first.** Compare NM_CONTACT_NODE_INCIDENCE_SORT=1 against the unchanged baseline, then separately NUMI_HUMAN_RESTING_COUPLED_TANGENT_BLOCK=1. Reuse the contact-sort reference/native checks, preconditioner GPU check, and exact integrated prefix. If either is slower, record why and leave it off. Do not batch flags together and lose attribution. Stop after the short paired measurements; no long run until there is a useful reduction.
3. **Remove work at its owner.** Implement GPU-written active dispatch counts for the measured expensive converged tails, and prune empty field work. Maintain any required zero initialization, true residual formation, final certification and commit/rollback operations. If contact dominates instead, fix incidence/surface sorting first. Reuse existing buffers/indirect infrastructure; a zero-grid dispatch may still have command overhead, so test active-command ranges or compatible kernel fusion if tails remain expensive. Reprofile total wall time after each coherent increment.
4. **Reduce necessary solve cost.** Improve the measured contact/constitutive/reduction bottleneck and use existing block/regional preconditioning where it lowers total time. Reuse/factor within the same Newton candidate only when valid. If a new candidate or topology change invalidates a cache, rebuild it. Consider local mesh-quality repair or static condensation within the existing FEM owner only when conditioning data warrants it and anatomical mapping, mass, coupling and physical tests remain intact.
5. **Increase accepted physical time per unit work.** Starting from the unchanged 0.125 ms root, test 0.25, 0.5, 1 and 2 ms, with 4-5 ms only if supported by accuracy/convergence. Use the existing multirate/adaptive machinery and preserve controller/respiration clock semantics. Compare against dt/2 on matched accepted trajectories: authored residual/contact/mass/volume thresholds unchanged, finite positive J, no missed impacts, bounded energy/momentum errors, and convergent pressure-volume, airway-flow and transmitted-force traces. Predeclare a 1% relative change screen on nonzero integrated flow/impulse and pressure/volume summaries, with existing stricter bounds prevailing and absolute scales declared for near-zero quantities. This screen is numerical, not clinical validation. If dt fails, diagnose the object/constraint instead of accepting a weaker tolerance.
6. **Finish latency and qualify the actual coupled workload.** After the heavy work is reduced, tune per-kernel groups/specialization, fuse compatible passes, reuse command graphs, and increase bounded submission segments where Brain/observer semantics allow. Re-enable full respiratory regulation/gas transport and the native presentation path for the final timing measurement. Progress from the short accepted prefix to 1 s, 16 s and 60 s before the 330 s baseline and matched intervention. Report startup separately, but include steady physics, physiology, controller, trace and presentation work in the target. Do not infer full coupled performance from mechanics-only timing.

Every change must pass the owning check and a matched integrated accepted-state/forced-rejection test before promotion. Relevant existing tools include cardboard_contact_node_incidence_sort_check.cpp, cardboard_contact_node_incidence_sort_native_check.mm, cardboard_fgmres_preconditioner_gpu_check.mm and fgmres_true_residual_native_check.mm. Extend their coverage only where the optimized path creates a gap; tiny cardboard fixtures do not qualify Human performance. Preserve published failed runs and current untracked work. Run one large solver at a time on SSH numi, and keep at least 12 GiB free before qualification. No paid CI or hardware purchase is required by this plan.

## Explicit 0.1x time budget

For an accepted root dt, the complete steady wall budget is dt / 0.1. These are targets, not measured feasible timesteps:

| Root dt | Allowed wall/root at 0.1x | Time-advance gain versus current root | Further speedup required from current replay if work/root stayed constant |
| --- | --- | --- | --- |
| 0.125 ms | 1.25 ms | 1x | 10,492x |
| 0.5 ms | 5 ms | 4x | 2,623x |
| 2 ms | 20 ms | 16x | 656x |
| 5 ms | 50 ms | 40x | 262x |

With four microticks, the current 1.25 ms target leaves only 0.3125 ms per microtick before other work. This is why removing only a few bindings or changing threadgroup size is insufficient. Larger dt can also require more iterations, so its gain must be measured jointly rather than multiplied into a promised speedup.

At a validated 2 ms root, use 20 ms/root as the first concrete budget: at most 15 ms for continuum/contact/linear solve, 3 ms for articulation/muscle/Brain/cardiorespiratory work, and 2 ms for scheduling/observation/presentation overhead. These are allocation targets to guide profiling, not claims about current costs. If accurate 2 ms stepping or this budget is not attained, 0.1x remains unmet; revise the measured bottleneck or the existing FEM reduction instead of declaring success on a smaller scene.

Completion means at least 0.1x for the unchanged declared anatomical/physical scope in the coupled run, with timing identities, no unexplained rejected-step/state drift and unchanged physical acceptance. No speedup has been implemented or demonstrated by this audit.
