# Pressure-loaded cavity preload path review

Read-only scoped source review at `bcb4283e0c62ef3f6595d08707d657f209df01b7`.

There is an owner-supported **material-parameter prestress staging** API, `prepareNumiHumanFEMPrestressStage`, in `matter/include/numi/matter/numi_human.hpp:28-64`, implemented in `matter/src/numi_human.mm:423-540`. It interpolates validated `neutralValue`/`sourceValue` material parameters into each environment's `RuntimeStateSnapshot.environmentParameters`. Its public contract explicitly says it only stages bounded material parameters, does not claim equilibrium, and requires the caller to restore the snapshot, execute an accepted FEM transaction, and establish a convergence certificate (`numi_human.hpp:53-57`).

The Open Knee probe demonstrates that continuation pattern: it identifies ligament `initialStretch` targets (`apps/numilab_human_open_knee_ligament_probe.mm:673-689`), stages each fraction, restores it, runs a transaction, and checks the accepted snapshot (`:916-967`). That is a usable example for material-parameter prestress, not a pressure-loaded wall initializer. The scoped Matter runtime and Human source search found no callable quasi-static/equilibrium/preload solver that accepts cavity pressure or returns an equilibrium certificate.

The present aortic source is pinned to stable cavity `9007`, CVSim compartment `7`; initialization pressure is `referencePressure + (initialVolume-referenceVolume)/compliance` (`matter/tools/human_resting_runtime.hpp:876-891`). The production wall traction uses the existing pressure difference `vascularPhysical(...) - compartments[...].compliance.w` times the cavity gradient (`matter/src/metal/vascular.metalinc:451-462`); `nm_vascular_cavity_node_force` includes it in FEM node force (`:590-603`). The retained 8-root audit shows the aortic wall is the dominant transient owner: its terminal maximum displacement is about 2.36 mm, maximum speed 1.45 m/s, and minimum J 0.70617. The skin-fat shell moves about 26.1 µm with minimum J 0.98524. These values are in `terminal-object-audit.json`, parsed from the exact hashed raw native log.

Smallest useful extension: add an opt-in **Matter-owned pressure-loaded initialization/equilibration stage** that starts from the admitted snapshot, keeps the existing CVSim cavity pressure and wall-force law active, and runs the coupled accepted mechanics path until explicit force/velocity residual criteria converge. Return the resulting accepted snapshot and convergence diagnostics as startup state. Any staged continuation must finish at the unchanged admitted pressure and pass the same final residual checks; do not zero/subtract pressure or inject a balancing stress. The current material staging helper alone cannot perform that work.
