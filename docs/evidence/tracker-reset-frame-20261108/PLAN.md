Question: if one environment resets between scheduled camera captures, can its newly initialized tracker history contain a measurement of the previous scene? The prior mixed-status diagnostic established a shared batch render cadence, but did not exercise a reset. Competing explanations are that the reset path refreshes or invalidates the frame, versus it reducing the cached prior frame.

Use the existing two-environment native tracker fixture with 20 ms observation period, one committed initial camera frame, and no simulated physics. At the next observation, move only environment 0's tracked body by 0.20 m and set its reset mask. Environment 1 and the camera stay fixed. The fast 50 Hz arm renders on that observation; the slow 25 Hz arm does not. The initial scene, sensor, buffers, model, observations, and seed match. Repeat both arms. Capture the initial and post-reset tracker output, reset mask, global frame sequence, and measured positions. Prediction for the stale-frame model: the 25 Hz post-reset position equals its initial measurement and differs from the 50 Hz post-reset measurement for environment 0; environment 1 stays constant. The 50 Hz arm is a same-renderer forced-fresh reference, not an external calibration. Require visible finite results and an actual body displacement; report failure otherwise. This probe uses synthetic direct reset input, not an actual MetalWorld episode or physical rejection; no deployment or force claim follows.
