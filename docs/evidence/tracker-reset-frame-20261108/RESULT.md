# Preventing stale visual observations after reset

At main code commit `2203970e6`, the tracker maintains per-environment cached-frame freshness. A reset between batch camera captures invalidates that environment's cached frame until a new capture. While invalid, all published object-track history slots have zero visibility, position and velocity; all published masked-depth history slots report far/no-return and their derived features are zero. Other environments retain their existing frames, and the nominal batch camera schedule is unchanged. If a physical step fails after rendering, the failed environment's cached frame is invalidated because the prior pixels were overwritten; if no rendering occurred, its prior freshness bit is restored with tracker history.

This is containment, not a complete sensor transaction or a per-environment clock. Renderer pixels and metadata, actor output packets from a failed step, earlier generic task state, recurrent policy state, and partially executed GPU commands are not restored here. Some otherwise useful measurements may be withheld after a failed rendered step until the next capture. A new GPU dispatch and private buffer are introduced; their performance cost has not been measured. The tracker/renderer still requires serialized in-flight use. Instance identities in these tests are oracle perception. Both experimental CCD and augmented-Lagrangian contact remain disabled.

## Negative control and direct validation

The [preregistered direct experiment](PLAN.md) used two environments, 20 ms observation intervals, a moved tracked body and a reset only in environment 0. With the prior runtime, the 25 Hz reset observation reported the old x position `0.50244689`; a 50 Hz same-renderer fresh capture reported `0.593514681`. At 25 Hz the renderer was still on frame 0. These are synthetic reset inputs and pixel-derived positions, not physical-ground-truth calibration. Both runs repeated exactly.

In the candidate, a 25 Hz reset produced zero confidence, position, depth returns and features until frame 1. A 10 Hz run remained invalid for four intervening observations and recovered at the next frame; a 50 Hz reset received a fresh observation immediately. The second environment remained visible. All three arms repeated byte-for-byte. Native tests separately cover materialized depth, direct-winner depth, successful and failed reset outcomes, a sampled failure followed by an unsampled observation, and mixed world/contact status restoration across 72 history/freshness layout combinations. The sampled-failure test initially exposed old sparse depth features even after the current frame became invalid; `ctest-sampled-failure.log` preserves that failure. The final code suppresses all published history slots until fresh.

## Actual MetalWorld reset

The separately preregistered follow-up in [REPAIR-PLAN.md](REPAIR-PLAN.md) used the existing two-environment, 30-step Franka contact-capacity fixture with zero actions, four substeps, 20 ms control interval, a 10 Hz camera and no CCD. The probe captures the actual GPU reset masks and actor history before tracker writes, after tracker writes and after the physical-step callback. It is an object-track fixture; it does not qualify masked depth in a full MetalWorld rollout.

The reset masks were identical across old and candidate arms. On nonsampled control steps 14 and 27, environment 0 reset while environment 1 did not; on step 28 both reset. At all four reset/environment pairs, the old tracker published a visible old track and the candidate published zero for every track-history slot. The non-reset environment's captured actor history was byte-identical between arms on steps 14 and 27. At sampled step 15 the reset environment again had a visible track. Steps 14/0 and 27/0 were rejected physical steps and their candidate actor history restored the pre-visual snapshot; both environments accepted step 28 and retained the invalid track. The capture covers the callback boundary, not every task or policy state.

The old and candidate `q`, `v`, scene, world-status and reset-mask arrays match exactly. Each arm was repeated, with all its saved arrays identical across repeats. The integration build's q/v/scene/status/reset/actor/history captures are identical to the candidate. [analyze_world.py](analyze_world.py) checks the retained raw captures. There were five failed environment-steps and 55 accepted; status failures were deliberately induced, so this is not a robustness or speed benchmark.

## Native tests and provenance

The main build and integrated source `671da7487` each passed all 22 `metalrobo.visual.*` tests. A broad suite attempt initially had five tests not run because their targets had not been built (`ctest-all.log`). After building them, two shader-level tests failed because their direct kernel harnesses did not bind the new freshness buffer (`ctest-all-final.log`); those harnesses were updated and all 22 passed. A first direct-winner fixture also failed because the small image used the wrong camera intrinsics (`reset-tests.log`); the corrected calibrated fixture passes. No failed evidence was discarded.
