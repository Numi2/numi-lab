# Bounded native slider-owner midpoint experiment

This is a proposed engineering experiment, not a completed Matter transaction. The question is whether a strictly scoped MetalWorld owner can consume a staged slider velocity and publish the midpoint endpoint once, without adding gravity twice or changing any other owner path. This is preparation for, not a substitute for, coupled FEM/contact qualification.

Candidate scope: one environment and one fixed-root, unconstrained, one-DOF world-z prismatic joint, no contact solver, scenes, rods, damping, drive, velocity/position limits, other actuators, or extra effort producer. The device-physics program must explicitly advertise the midpoint candidate contract and MetalWorld must validate the actual compiled model, not trust only the callback. An accepted stage increment is delta = v_m - v_0. The published physical increment must be 2 delta. If MetalWorld ABA contributes gravity itself, the contribution from the extension must subtract the same gravity once. The accepted coordinate must be q_0 + h (v_0 + delta), not q_0 + h v_1. A missing candidate or unsupported topology must fail closed. Any owner API and fingerprint must distinguish this path from normal endpoint integration. Rejection must leave all authoritative state at the checkpoint.

Before connecting Matter, test actual MetalWorld accepted transactions against closed-form free fall and separately a constant vertical load for two nonzero timesteps and initial velocities. Test a rejected candidate and retry, exact restored q/v, and rejection of an incompatible rotating joint and another actuator. Verify the legacy owner path remains unchanged. Use full-step momentum and position residuals; sampled output or a candidate scratch endpoint alone is not an acceptance certificate. Preserve any failed attempt and do not infer physical contact, torque, work, replay of Matter state, spatial accuracy or a performance benefit from this owner-only fixture.

The production path must remain disabled until the two-owner path additionally solves FEM and rigid contact together, certifies both local physical residuals and geometric endpoint clearance, publishes the impulse and torque with consistent work, and passes whole-environment rejection/retry. Those requirements are specified in `DYNAMIC_MIDPOINT_EQUATIONS.md`.
