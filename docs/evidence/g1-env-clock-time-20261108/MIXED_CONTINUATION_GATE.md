# Future mixed-phase continuation gate

The following is a test specification, not a claimed result. Use a separately sealed fixture at 25 Hz and a 20 ms control step. After two accepted nonterminal steps, inject the existing real environment-0 overflow while environment 1 succeeds. Under accepted-step scheduling, before reset the next environment-0 observation would request sensor sequence 1 (fresh relative to its last accepted sequence 0), while environment 1 at accepted count 3 would hold sequence 1. That creates a real sample/hold disagreement; a shared batch decision must not be accepted as the answer.

Build same-identity reference trajectories with independently controlled per-environment initial physical, visual and task state; ensure the reference has identical instance/environment seed inputs, sensor configuration, timestamps and policy inputs. Compare every frame plane, camera, tracker and actor record, per-environment frame/sensor identity and capture time bitwise, as well as the noise-derived target pixels; verify that changing the expected accepted sensor/frame sequence changes the actual seed-dependent pixel values, while an identical accepted sequence exactly replays. Require the baseline to demonstrate a target pixel and a noise response on both fresh and held reference frames; an invisible or noise-insensitive target is an inconclusive prerequisite.

The owner marks the rejected environment terminal and normally resets it next. First qualify this real automatic-reset continuation with its exact task reset mask and declared clock/metadata reset semantics. An additional no-reset retry is a separate test-only mode requiring a faithful resident retry and independently verified matching pre-retry physical and task state; it cannot be inferred from a reset. Both test real accepted/rejected statuses and all intermediate records, and must compare against separately controlled references. Before lifting the guard, separately qualify masked-depth ring/episode interaction, reset-accepted and reset-rejected transitions, command-buffer failure, and multi-step submission or explicitly reject those modes. This study is not executable on the present batch-sequence renderer; a true per-environment frame/seed/metadata implementation and faithful reset/reference harness are still required.
