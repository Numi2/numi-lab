# Integrated masked-depth feedback and physical rejection

The earlier 30-step Franka masked-depth feedback test predates the actor-output rollback repair; the later full-step rollback test uses zero actions and object tracks only. This experiment joins them on the current integrated MetalWorld owner. Hypothesis: with the existing stateless sensor-feedback GPU controller and both object tracks and masked depth, each accepted environment publishes its post-tracker observation; each rejected non-reset environment restores its pre-tracker observation; each rejected reset environment keeps nonvisual values and clears track/depth/feature visual output. The controller consumes pre-physics observations, and its captured actions must agree with an independent CPU depth reduction. A failed physical step is not treated as a successful transition.

Derive from the retained tracker-masked-policy probe and add read-only blits before/after tracker encoding and after the physical callback, using the output-buffer capture from the later tracker-output probe. Preserve two environments, 30 x 20 ms, four substeps, 10 Hz camera, raw-contact capacity one, initial geometry, 35% depth dropout, 160 x 120 masked depth, and two depth histories. Identity masking is oracle perception. Run twice with matching model and runtime. Require exact repetition of all captured output, inputs, actions, resets, status and exposed state. Require mixed accepted/rejected steps, rejected reset and non-reset cases, nonzero changes by the tracker on a rejected non-reset and accepted step, nonzero fresh feedback, and a reset with stale camera where all tracks and features are zero and depths report far before the action. Compare all 60 actions to CPU recomputation and ensure the surviving neighbor remains responsive. Fail if any condition is missing or data are nonfinite. Keep failed runs and do not retune fixture or thresholds after inspection.

This confirms only the observed stateless reset, feedback and output publication contract. It does not establish recurrent-policy rollback, GPU-command failure recovery, private renderer pixels, per-environment accepted sensor time, deployment-valid perception, learned task success, force accuracy, or speed.
