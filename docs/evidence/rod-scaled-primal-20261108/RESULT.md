# Isolated coupled rod stretch and attachment prototype

**Result:** a research-only Metal solver now passes the declared synthetic stretch-and-attachment screens, including a 20-step continuation. This is not a production rod repair. The production rod source was not changed, and the earlier false acceptance remains relevant to it. The prototype does not implement bending, twist, self-contact, tool contact, rigid-body coupling, resident ownership, or a calibrated suture.

The work began from the retained three-node false acceptance in `../rod-balanced-constraint-20261108`. A scaled FP32 primal displacement solve passed all 16 preregistered straight axial cases through 127 nodes. In the subsequent 3D vector screen, the first block Gauss–Newton method passed only 4/10 cases; its block linear solve matched a separate dense solve, but curved and moving cases did not converge within the budget. Adding the complete geometric stretch Hessian improved the result to 9/10, with the moving-endpoint position still outside the 1e-6 m gate. Tightening the working force threshold fixed that case but exposed FP32 stagnation (4/10). Holding local position increments improved it to 8/10. Computing length changes by a rationalized difference and line-search objective changes term by term produced 10/10 in the CPU FP32 screen. These separate results and their plans are retained; no failed output was overwritten.

An independent FP64 energy-difference audit passed 44/44 comparisons, including 40 informative sign checks; reversing the sign failed all 40. The first audit launch used a source split that produced a syntax error, which is retained as `energy-audit-initial.log`; the corrected audit was run separately. This audit concerns the registered synthetic stretch objective and uses the same quantized input edges, not a physical material measurement.

The standalone `rod_block_prototype.metal` implements the scaled vector block solve, local increments and stable energy differences. On the Apple M6 it passed all 10 registered primary cases and all 12 previously unused, seed-20261109 rotated/curved/translated held-out cases against dense FP64 references. The largest all-node position errors were 1.257e-8 m and 4.289e-8 m respectively, and the largest independently recomputed published-coordinate local force residuals were 2.415e-6 N and 3.774e-6 N. All support-reaction gates passed. The working-increment residual can be smaller than the force residual recomputed from rounded, published positions; both were recorded and the latter has its own 1e-5 N gate. These 22 cases use 3–17 nodes and are one-step tests, not the earlier 127-node scalar experiment.

The malformed-input batch rejected invalid node count, a zero-length edge, a nonfinite position and nonpositive mass with nonzero status while retaining all sentinel position/reaction bytes; its valid control passed. The first source build failed on a Metal matrix unary-minus expression and is retained as `metal-build-initial.log`. The first compression-control invocation used a system Python without NumPy; `compression-initial-failure.log` records it, and the pinned environment ran the control.

A subsequent compressed three-node control exposed an additional failure: the v2 prototype published a zero-force stationary state whose independently evaluated free-node Hessian eigenvalues were approximately -109.44, -109.44 and +81.11 N/m. The failed v2 source and output remain in `rod_block_v2.metal` and `metal-compression-v2-failure.*`. The final prototype checks positive block pivots before accepting a small force residual; it rejects that control with status 2 and leaves the caller position/reaction bytes untouched. The ten primary cases, twelve held-out cases and malformed-input batch still pass. This fail-closed check establishes only a local negative-curvature guard for this objective; it does not resolve compressed motion or prove global stability.

The final standalone kernel was then used for three consecutive 20-step, 1 ms trajectories: straight with a moving interior, curved with fixed ends, and curved with a moving hard end plus an interior compliant anchor. All 60 case-steps passed the declared position, support-reaction and independently recomputed local-force gates against separately advanced FP64 reference states. The maximum trajectory position error was 2.839e-8 m and maximum local force residual 3.761e-6 N. The moving-support work was 1.85839084e-6 J versus 1.85864038e-6 J reference, within the registered 2% or 1e-9 J gate. Support impulses, final kinetic-plus-potential energies, individual step results and reference values are in `metal-trajectory.json`. The two fixed-end work values are zero. Each GPU state and its finite-difference velocity were carried by the host to the next step; this is not a resident GPU physical trajectory or proof of MetalWorld transaction semantics.

The final primary, held-out, malformed, compression and complete trajectory output buffers repeated byte-for-byte (`final-repeat.log`). The initial and intermediate failures, generated inputs, raw GPU outputs, independent analysis and scripts are retained. Final compiled AIR, metallib and host executable are in `native-artifacts/`; all evidence files are hashed in `artifact-sha256.txt`. `host.txt` records the toolchain and `source-revision.txt` pins the surrounding repository. Runs were correctness captures, not performance measurements. Experimental directional CCD and augmented-Lagrangian contact were not enabled.

Next, derive and verify a coupled vector method for the existing DER bending and torsional energy, then add contact and dynamic attachment response with independent force, torque, work and negative-curvature checks. Extend the state contract to GPU-resident accepted/rejected steps, restoration of all owner caches and moving-body action–reaction. Only after those checks can an implementation replace or guard the real rod solver. The earned tissue bridge, physical material calibration and continuous suture remain unresolved.
