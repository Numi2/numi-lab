# Per-environment HyperPolicy physical-step restoration

The preregistered debug run reproduced five physical failures; three have no reset. On two mixed outcomes an environment's accepted policy phase and previous action advanced despite rejection, while the neighbor succeeded. The read-only debug accessor preserves every non-diagnostic output exactly against a same-source noninstrumented run, and both repeats match.

Introduce an optional post-physical-step action callback, leaving legacy stateless action callbacks valid. HyperPolicy snapshots its complete phase record and prior physical actions on the owning command buffer before policy evaluation. After each physical step it restores those snapshots only for environments whose world status or, when enabled, contact status reports failure. Reuse the existing status semantics and do not commit or wait in callbacks. Preserve successful neighbors. The disabled CCD and AL options remain untouched.

Before considering integration, rebuild the native runtime and shader; repeat the real 30-step two-environment test with direct pre/post private-state snapshots and a noninstrumented paired run. Check every failed environment restores the full phase record and action row, every successful environment retains its candidate state, and candidate state on accepted steps agrees with an independent control. Include both contact-enabled and contact-disabled status handling in a focused kernel test if feasible, retained same-capacity and growth/host-abort regression, non-instrumented repeated q/v/scene/status/task outputs, and explicit failed-step reporting. Do not claim a completed task or a general GPU-command rollback guarantee. A command-buffer execution failure and overlapping submissions need separate transaction ownership.
