# Uncommitted successful visual observation: diagnostic

Use the already qualified two-environment native visual-platform probe on the pinned main source and library. Compare its normal control with a fault arm which successfully encodes one extra observation on a fresh command buffer after the first accepted sample, but deliberately never commits that buffer, modeling a later host-side rejection. Then run the probe's existing rejected-encode check and valid retry without changing the scene, tracker, sensor cadence or test gates. Report renderer metadata immediately before and after the discarded encode and the valid retry's sensor sequence. The no-fault retry must be sequence 1; transaction-correct behavior would give sequence 1 in the fault arm too. A fault-arm sequence 2 is evidence of a pre-submit cadence leak, not a physical-step or mixed-environment rollback test. The GPU work from the discarded command must not execute. Retain all output, code, binaries and hashes and do not infer a fix from this test.
