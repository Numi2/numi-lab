# Successful observation encoded into a discarded command

A native Apple M6 visual probe exposes a pre-submission sensor-transaction defect. After its first accepted sensor sample, the fault arm successfully encodes another real tracker observation into a separate Metal command buffer and never commits that buffer. Renderer metadata changes immediately from sensor sequence 0 to 1. The original probe then fails its existing assertion that the most recently accepted frame is sequence 0. The matched no-fault control completes with exit 0.

A separate diagnostic binary retains that failure as a logged failed assertion but bypasses it only for the fault arm, so the subsequent retry can be observed. Its no-fault control reports `retry_sensor_sequence=1`; the discarded-encode arm reports `retry_sensor_sequence=2` and fails the unchanged retry assertion. The existing invalid-encode negative check remains in both paths. These results demonstrate premature host metadata and cadence advancement for a successful encode discarded before submission. The uncommitted command did not execute GPU work. The probe is not an actual MetalWorld rejected physical step, a mixed-environment test, or a proof about post-submission GPU-state restoration.

The tested source was main revision `3a8e4ddea` (its preceding two commits after the last native build add evidence only); exact source, probe, library and shader hashes, inputs, controls, failure exits, build output and binaries are in `diagnostic.tar.gz`. The compiled library and shader hashes match the retained previous native qualification. Archive SHA-256: `39805d5e4ce15c4ba1d895b107d20fba550a7ce9a403d4ffd1cabf87a71e5b6c`. An independent extraction passed its entire portable hash manifest and programmatically checked the observed control and failure outputs. The diagnostic-only assertion bypass and the original earlier failure are both retained; neither changes production code.

The tracker currently advances host `observationSequence`, `lastSensorSequence` and its render uniforms on successful encode, while the materialized renderer updates `activeMetadata` while encoding. MetalWorld's observation callback interface does not supply an abort or acceptance notification. A later host rejection can therefore abandon encoded GPU work after host state has already changed. Fixing only the initial failing-encode path does not cover this case.

Next implement a lifecycle that reserves the relevant observation owner for a submission, stages host cadence and metadata, and aborts or publishes them at the actual owning transaction boundary. Qualify the real MetalWorld path with a later callback rejection and an identical no-fault retry; then separately handle per-environment physical acceptance, private GPU track/depth histories, renderer output, reset state and post-submit failure with matched rejected-versus-no-rejection controls. Any concurrent or shared renderer owner must be explicitly excluded or coordinated. A simple global rewind on command completion is insufficient for mixed acceptance or overlapping submissions. Keep the two experimental collision/contact options disabled.
