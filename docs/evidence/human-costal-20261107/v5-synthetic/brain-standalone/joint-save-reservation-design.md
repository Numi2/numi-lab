# Joint diagnostic save reservation — design, not an implemented checkpoint

## Locking gap

`withDomainPublicReadGate` holds the publication domain's shared gate and prevents the joint publication writer from crossing it. It does not exclude a new native `beginPhysicalRoot`: that path separately takes `RuntimeState::mutex`, checks `beginInProgress` and `active`, then sets `beginInProgress`. Thus checking `active == nullptr`, dropping the mutex, and reading Matter/Human under the shared publication gate is not an atomic snapshot. Holding only Brain's lock does not itself reserve the native runtime. `Runtime::snapshot()` rejects a borrowed active transaction, and `flushPhysicalStateObserver` rejects an in-flight or prepared owner, but independently successful reads do not prove a single common boundary.

## Minimum proposed protocol

1. A synchronous diagnostic coordinator takes the Brain runtime lock first, fails closed if a control is open or its components disagree, and records its committed generation. It must retain this lock for the whole operation. Refactor the existing Brain checkpoint implementation into a lock-held internal helper; do not recursively call its public lock-taking API.
2. While still holding Brain's lock, acquire the domain's shared public gate, then atomically reserve native saving under `RuntimeState::mutex`. Verify no begin is in progress, no active or quarantined root exists, no publication is poisoned, the aggregate is published, and its epoch and Brain/physics identities match the locked Brain. A dedicated `saveReservation` flag is preferable to reusing `beginInProgress`; both legacy and exact begin paths and any other mutator must reject or report busy while it is set. Lock order must be audited end to end: **Brain → public gate → runtime mutex → owner adapter → Matter → HumanIO**. The public gate must never call a Brain getter or acquire the Brain lock; all Brain access is performed by the outer lock-owning coordinator.
3. Release the runtime mutex after installing the reservation; retain the reservation, Brain lock and public gate. On the owner's queue, capture and validate the four exposed authoritative Human arenas and accepted identity. Capture a quiescent Matter snapshot and archive using its ABI-bound serializer. Also capture published HumanIO sensor payload/identity and any configured continuation authority; do not silently assume the observer's four buffers represent all Human or adapter state. Verify that epoch, generations and accepted identities remain the same at completion.
4. Construct an immutable, versioned physical artifact that includes the exact Human and Matter content and all required configuration/identity fields; hash the artifact and bind its fingerprint to the Brain checkpoint using the lock-held internal helper. Persist both with a receipt after both succeed, and publish the receipt atomically only after all components and checksums are durable. The physical artifact and fingerprint must be real, not the aggregate transaction identity or an invented constant. The initial version should be explicitly a **comparison artifact**, not an advertised restorable checkpoint, until restoration and every state owner are verified.
5. A scope-owned reservation clears the save flag on every pre-dispatch failure, callback failure and normal return; release locks in reverse order. If a GPU observation has been submitted but cannot be confirmed complete, do not clear the reservation while the command could still access borrowed state: retain/quarantine it until real completion or an explicit terminal teardown. A caller timeout is not proof that device work was cancelled. The public gate and Brain lock must not be abandoned by destroying a thread-owned lock on another thread; a production design must define safe completion ownership before adding asynchronous timeout behavior. An immediately busy nonblocking admission is preferable to an unbounded lock wait.

## Required tests before claiming an atomic save

- Initial, no-published-root, poisoned, active-control, active-native-root and begin-in-progress requests all fail without publishing an artifact or changing accepted state.
- A scheduled begin racing reservation is either admitted before the save (save fails busy) or rejected while the reservation is held. A publication racing the save cannot produce a mixed epoch. Test both orderings with explicit barriers; do not rely on timing.
- Inject failure at each acquisition, allocation, encode, Matter snapshot/archive, Human observation, Brain checkpoint, checksum and receipt-write stage. Verify no partial final receipt and prove the reservation is cleared on every synchronous failure, with the next valid root admissible.
- Inject a stalled or failed GPU completion. Verify timeout returns a distinct pending/quarantined result, retains all borrowed resources and excludes new roots until actual completion or terminal teardown; prove no lock is unlocked on a different thread. These tests require a real cancellable/observable command lifecycle, not a fabricated success.
- Independently verify saved file bytes and identities, reject tampering and mixed generations, compare all enumerated authoritative fields before/after forced rejection, and compare a retry against a matched no-rejection control. Account separately for reservation counters that intentionally advance on rejection. Only then can full-state restoration or replay be assessed.

No reservation or joint checkpoint has been implemented by this document. The previously passed synthetic aggregate-level checks remain narrower than these requirements.
