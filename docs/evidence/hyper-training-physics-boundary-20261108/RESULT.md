# Prevent numerical failures from contaminating policy training

This repair addresses three boundaries in the existing training implementation. The normal PPO worker already rejected a rollout containing physics_error; direct calls to NativePolicyRollout.policy_batch did not. The direct API now rejects the same input. HyperPolicy specialist training previously assigned invalid samples zero loss weight, but calculated reward ranks and tracking extrema over every sample. A failed or terminal sample could therefore change the weights of otherwise accepted samples. Normalization now uses only samples eligible for teacher supervision, and excluded rows are removed before the specialist actor sees them. A rollout with no eligible samples is rejected. HyperPolicy meta-training now rejects any numerical-failure rollout before treating its user-supplied qualified flag as a motion-level physical outcome label.

The eligibility rule is unchanged: physics_error must be zero and a terminal row is eligible only when it is a timeout. Invalid rows are also excluded from normalization; consequently training weights can change in rollouts containing rejected or non-timeout terminal rows. All-eligible rollout weights are preserved. These are training-semantics changes; they do not repair sensor clocks, transaction replay or the physical solver.

The retained synthetic regression changes only the failed row's reward, tracking, teacher action and observation while keeping accepted rows fixed. Against the parent source, the tests show accepted weights change, invalid extreme inputs can contaminate the MLX specialist update, the direct PPO API accepts a numerical failure, and meta-training admits it as an outcome. The full baseline is in baseline.log. The candidate passes 11 tests on MLX CPU and Apple M6 GPU: accepted-weight invariance with and without tracking, terminal/timeout eligibility, all-invalid refusal, clean controls, and a real paired MLX specialist optimization update with bit-identical exported parameters and metrics after changing the rejected row. Clean meta-training preserves explicit success and failure labels, while physics-error meta-input and direct PPO input are rejected. The existing synthetic generic policy selection evidence test also passes. Test runs are not timing measurements.

The tests use constructed rollout records and a small synthetic actor, not an actual native physical training run, an independently reproduced sensor failure, trained task skill, or proof that all post-failure accepted observations are transactionally valid. The specialist may still train on other individually eligible samples in a mixed rollout; their physical and sensor provenance remains the runtime owner's responsibility. Motion-level meta-training and direct PPO conversion reject the complete contaminated rollout. Existing native worker validation remains in place.

Run from the repository root with an MLX- and NumPy-enabled Python:

    PYTHONPATH=python python tests/hyper_policy_failure_training_test.py
    PYTHONPATH=python NUMI_TEST_MLX_DEVICE=gpu python tests/hyper_policy_failure_training_test.py

The test is part of the existing *_test.py Python unittest discovery and skips when MLX is not installed. baseline.log is produced by loading the two parent-source modules against the otherwise unchanged package and current test. Parent source and candidate files are identified in source-sha256.txt. Both experimental CCD and augmented-Lagrangian options remain disabled.
