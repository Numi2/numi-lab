# Synchronized-clock renderer attachment and fail-closed continuation gate

This separate isolated single-step fixture connects the renderer's sample decision to the per-environment accepted clock only after two successful, nonterminal steps. It seeds both records to `(acceptedSteps=2,lastSensor=1,captureStep=1,captureTimeBits=0)` for the already established 50 Hz sequence, then computes candidates with the same double calculation used by the renderer. The final word is an opaque test marker and is **not** validated renderer capture-time metadata. The finish hook uses the real per-environment MetalWorld and contact statuses to commit candidate records. All renderer sample decisions are accepted only when every accepted clock agrees with the existing batch host sequence; masked depth and divergent clocks are rejected. The old prepare-hook divergence guard remains active. Production defaults and reset behavior are unchanged.

Run this candidate with exact snapshot readback and once without it, each with 120 seconds. Both arms must complete two successful nonterminal steps, display a visible tracked target, and produce the expected step-3 all-success control and real mixed contact overflow. Record sensor proposals, four accepted record words and exact actor/tracker/frame buffers; require both control clocks to advance at steps 3 and 4, failed env 0 to remain `(2,1,1,0)` at step 3 and successful env 1 to become `(3,2,2,1003)`. The unobserved and observed output streams must match at printed precision. On the attempted failure-arm fourth step, require the existing divergence guard to be entered and explicitly refuse the command before observation, and compare its private tracker/frame snapshot against phase 3. Do not call this independent-cadence continuation: it is the negative gate that must remain in place until real sample/hold, random seeds, renderer metadata and reset all qualify. The proposed metadata marker tests status-gated ownership only. A positive mixed continuation, reset, masked-depth rings, GPU command failure, multi-step graphs and real sensor calibration are not qualified.

The earlier candidate dylib was overwritten; see PROVENANCE.md. These are fresh copied binary, shader and asset identities, not a recreation of that prior execution. If any prerequisite fails, retain it and stop rather than relaxing the gate.
