# Exact native Float32 frame registration

The source-only full-Human registered-volume import used to require a Float64 near-SO(3) bound on matrices reconstructed by the native Float32 quaternion code. Some actual source-rest matrices exceed that default bound by a few Float32 rounding units. Reconstructing those matrices in a separate Python or C++ helper also differed from the native executable. Normalizing them would change the pinned native frame.

The native owner now exports its exact widened-Float32 local-to-world matrix in the existing opt-in all-body pose snapshot. One shared native function supplies both that capture and the importer pins. Existing pose fields and ten parent data outputs remained unchanged in the actual source-only capture. Normal snapshots without the existing all-body opt-in retain their previous representation.

External CSV frames retain the strict existing rotation checks. Only the native owner can provide an internal trusted donor-frame table. A CSV using that path must match the exact native binding, origins and matrices and pass finite Float32 representability plus a bounded 8-epsilon-Float32 orthogonality/determinant check. The CSV cannot select a weaker arithmetic mode. The complete native body table carries the same explicit arithmetic policy. This bound stays inside the physical volume owner’s existing 1e-6 rotation bound. The 314 captured current/rest matrices had maximum orthogonality error 6.405672419e-7 and determinant error 6.285462273e-7.

A rounded native matrix is not exactly orthogonal: its transpose is not its inverse. Native-Float32 registration therefore computes the true 3x3 inverse in double precision for local coordinates. O/I/D sidecar validation, volume import and the role consumer use that same rule. Derived inverse matrices permit only eight Float64 epsilon units of entry rounding between inverse implementations. The exact native local-to-world pins and existing point reconstruction, provenance, mass and physical-admission gates remain mandatory. The legacy external/fixture route retains its previous transpose behavior.

Focused checks cover unchanged strict defaults, exact native pins, a one-Float32-ULP mismatch, origin mismatch, reflection, shear, non-Float32 data, excessive rotation error, wrong donor domains, full unbound body-table rows and inverse round-trip reconstruction. Existing registered import and role-consumer tests continue to pass.

These changes affect CPU source preparation and coordinate registration, not the per-step Metal mechanics or physiological state owner. A positive preparation control does not admit repaired tissue or demonstrate motion. Failed control attempts remain retained beside the tests; physical installation and motion require the actual repaired volume and existing acceptance checks.
