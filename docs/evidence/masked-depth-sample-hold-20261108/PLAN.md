# Masked-depth measurement hold between scheduled captures

Question: Does a camera frame retain the same corrupted pixels while its batch renderer has not captured another frame? The current kernel keys corruption to task episode step even when the renderer does not sample. The intended contract for this repair is sample-and-hold: the entire normalized corrupted frame, including dropout and jitter, is sampled once per scheduled capture and reused at intervening accepted control observations; the history ring still advances per control observation. A reset with no fresh capture remains invalid/far until a new capture, and rejection retains existing per-environment history/freshness behavior.

Before changing production code, run a new native test using the existing materialized renderer fixture, two environments, 20 ms controls and 25 Hz camera, with its existing nonzero dropout and noise. Observe initial sample, intervening hold, next sample and second hold. Require byte-exact pixels from each sample to its hold for both environments, and a changed sample at the next actual capture. Repeat. For the direct-winner shader path, additionally use the existing dedicated shader fixture with independent materialized/direct-winner cases and explicit sampled versus held status, nonzero corruption, history offsets, invalid freshness, reset and singleton ring capacity. Capture baseline failure first. Use unchanged seeded inputs. A sample-hold assertion is a product contract, not a physical sensor calibration.

If confirmed, pass the existing batch sample decision into the masked-depth kernel and copy the last accepted frame into the next ring position on an unsampled, non-reset, fresh observation. Keep resets and failed-step snapshot restoration; do not claim this fixes shared batch cadence, per-environment accepted time, stochastic renderer keys, renderer buffer restoration or physical calibration. Run visual and transaction tests, compare actual physical acceptance and neighbor behavior on the retained mixed-status fixture if feasible, preserve failures, identify exact binaries and source. Keep directional CCD and augmented-Lagrangian options disabled.
