# Surgical checkpoint integrity gate

At source commit `5651c79fa`, the surgical handoff loader rejects a v3 checkpoint if any rod twist or twist-rate record is missing. Previously, an incomplete set caused every edge to be silently replaced with zero. Duplicate schema, phase, step, generalized-state, needle, node, and twist records are also rejected, including a duplicate schema that attempts to downgrade a v3 record. Legacy v2 records may omit all twist records, but a partial set is rejected; v2 remains insufficient for Matter checkpoint restoration. These checks run before the decoded state is applied to the world.

On `ssh numi`, Apple M6, the retained [CTest log](ctest.log) shows four native tests passing: tissue-rest creation, v3 restore without advancing, integrity cases, and the existing restore/rewind/hold test. The integrity test deletes one or all twist records, duplicates authoritative fields, attempts a v3-to-v2 duplicate-schema downgrade, and tests absent and partial v2 twist sets. It verifies the original fixture bytes stay unchanged. [SHA256SUMS](SHA256SUMS) binds the executable, library, shader and material file. The fixture is synthetic tissue-rest; it does not establish accurate force, surgery, or full uninterrupted resident equivalence. The hold test cold-initializes MetalWorld contact history, as documented in `docs/METAL_WORLD.md`; no new multi-owner or atomic restoration claim is made.

The first test invocation failed because this sparse checkout had omitted the tracked porcine material file; restore and hold were not run. Adding the exact tracked file to the sparse checkout allowed the reported passing run. The failure was setup-related and is not a successful physics result.
