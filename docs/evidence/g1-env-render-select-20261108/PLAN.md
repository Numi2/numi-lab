# Preregistered real-render and real-status selection diagnostic

This bounded research harness runs the actual two-environment task with 5 mm depth noise, two accepted nonterminal steps and the existing real step-3 contact-overflow trigger. The finish hook retains the MetalWorld-owned world and contact status buffers. After the failed command completes, the harness does not resume the rollout. Instead, it independently renders the retained observation-time body pose twice at frame/sensor 2/1 and 0/0 and repeats both reference renders. Require successful rendering, repeated depth/identity/validity/metadata words matching exactly, both targets visible and noise-sensitive at the fixed pose. Camera references are checked by float equality; raw camera words are retained for later comparison.

A separate diagnostic GPU kernel then uses the **actual** retained per-environment world/contact status buffers to select among the two actual renderer outputs for depth, identity, validity, camera and per-environment copies of frame metadata. Two injected proposal masks are tested: `(fresh,hold)` and `(hold,fresh)`. The masks are deliberately test inputs, not decisions computed by a real divergent renderer clock. In both scenarios rejected env 0 must retain every held word; successful env 1 must retain held or accept fresh respectively. Compare every selected word against the independently retained rendered references; require both distinct noise-sensitive pixel changes and actual env-0 overflow / env-1 success. These frame sequences are diagnostic alternatives for a fixed pose, not a chronological retry trajectory.

Run once with a 120-second timeout and verify frozen input hashes before and after; retain all outputs and failures. The kernel is downstream post-step research instrumentation, not the real renderer's transactional publication path. This gate does not establish live mixed-cadence continuation, accepted clock ownership of proposals, reset semantics, actor/tracker publication, masked-depth rings, or command-failure atomicity. The existing guard remains enabled.
