# Explicit coupled-rod model API on Apple M6

An isolated research branch exposes the existing compensated-force coupled-rod candidate through `DiscreteElasticRodModel`, `DiscreteElasticRodState` and two hard endpoint attachments. This is a separate explicit API; neither MetalWorld nor the existing standalone XPBD API selects it. It rejects unsupported topology, material, attachments, unrepresentable inputs, Metal failures and uncertified GPU outcomes without modifying its output. It does not silently fall back. Its documented scope is a single, straight-rest, uniform isotropic 3–9-node rod, with no gravity, damping or contact. Its residual diagnostics are GPU estimates plus measured public-state conversion error, not independent FP64 certificates. Device timestep and coefficients are FP32.

The normal CMake library and full metallib built at source revision `85aff7a56` (the subsequent evidence-only commit changes no source). The two registered CTests pass. The existing standalone CPU and Metal rod probes also complete; these controls do not establish that their known false-acceptance defect is repaired.

The prior exposed and previously unused sets each pass 12/12 one-step physical gates twice using the normal-built API, with byte-identical repeated result files. These sets were observed before this experiment and are not new holdouts. Across both sets, maximum errors against the native-energy reference are 1.32e-9 m position, 1.33e-6 m/s velocity, 1.09e-8 rad twist, 2.36e-5 rad/s twist rate and 7.51e-9 N support force. Independently evaluated local linear and angular momentum residuals reach 0.000184 m/s and 0.0000905 rad/s; all meet the previously declared gates. The reference checks the same discrete model and is not physical material calibration.

A separate closed-form three-node axial reference tests 27 combinations of radius, Young modulus and timestep with both supports moving. All 27 pass twice with identical output; maximum errors are 1.26e-11 m position, 2.51e-8 m/s velocity, 2.35e-6 m/s local momentum residual and 5.38e-10 N reaction. This validates the admitted simple axial cases, not general 3D contact or calibrated material response.

The previously observed three ten-step trajectories also complete 30/30 steps twice, carrying the public state on the host between API calls. The reference independently advances using native energy derivatives. Both repetitions have identical result files and native-query traces. Maximum position, velocity, twist and twist-rate errors are 2.51e-9 m, 4.02e-6 m/s, 2.08e-7 rad and 2.47e-5 rad/s; maximum support-force error is 8.00e-9 N and maximum linear and angular momentum residuals are 0.000210 m/s and 0.000103 rad/s. The predeclared work and energy checks also pass. This is not a resident or MetalWorld trajectory.

The first implementation **failed** the separately registered publication check: with a common twist of 1e12 rad and an initial rate of 0.001 rad/s, it reported success after the public double state rounded the twist increment away and returned zero rate. `publication-baseline.log` preserves that failure. The new guard includes conversion error in the admission check and rejects the same step with output unchanged; unsupported material, degenerate geometry, nonfinite input, compliant support and missing metallib controls also reject without altering the sentinel. The zero-load control succeeds. The earlier baseline and candidate raw data remain in this directory.

The first attempt to start the matrix failed before launching a case because the default Python lacked NumPy; that stderr is retained. Later initial native-run scheduling could have overlapped another GPU probe, so `exclusive-*` records the repeated matrix after checking for competing task-owned jobs. No timing or speedup is claimed. Hash manifests bind the source and native artifacts before the relevant tests and their postchecks. Complete trajectory outputs and native queries are retained; build and CTest logs are included.

This research API does **not** fix production false acceptance, integrate with MetalWorld, preserve paired precision across its event/checkpoint/contact consumers, qualify genuine GPU command loss, validate coupled rigid or tissue reactions, or establish suturing and physical realism. The research branch is not promoted to production. Next, carry the paired state through the real MetalWorld transaction and public checkpoint contract, then test actual coupled owner failure/retry and noncontact and contact motion before considering selection. The experimental directional CCD and augmented-Lagrangian contact options remain disabled.
