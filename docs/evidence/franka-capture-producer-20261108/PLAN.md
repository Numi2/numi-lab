# Real-render synchronous frame producer feasibility

This non-G1 standalone research producer owns a real Franka WorldFamily and fast hybrid renderer, serially calls the actual render method and checks its completion diagnostics, then calls and checks the actual readback method before publishing an immutable copied batch with a monotonically increasing generation. Both renderer methods wait for their own Metal command and return failure if that command did not complete. This wrapper is fixture-only and exclusively owns each renderer during its calls. It reports whole-batch success; it has no independent per-environment completion signal and is not connected to policy or physics.

The four-environment visible scene must yield a completed frame with geometry and FRAME validity in every environment. An out-of-capacity five-environment request must be rejected and leave the last accepted object and generation unchanged. A subsequent valid capture must succeed with a new generation. A separately compiled scene with the Gaussian beyond the view must yield a completed present frame with FRAME validity and zero geometry for every environment. Frame presence is determined solely by completed render and readback, not inferred from pixel content. Save depth, validity, identities and metadata for each published capture. Compare visible and retry bytes after their different wrapper generation fields, retaining mismatches rather than assuming deterministic output. Empty scene visibility and out-of-capacity rejection are mandatory gates.

One pinned process, 120-second timeout, exclusive GPU, exact input hashes before/after, no retries. Out-of-capacity rejection occurs before dispatch; it is not a GPU command failure. This does not qualify GPU-failure rollback, asynchronous or per-environment capture completion, interleaving callers, mixed physics acceptance, deployed camera perception, fingerprint migration or production actor integration. Existing renderer and production defaults are unchanged.
