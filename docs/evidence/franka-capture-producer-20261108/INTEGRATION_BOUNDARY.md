# Capture completion and task observation integration boundary

The synchronous producer result is a standalone feasibility result, not an observation-path implementation. The current task owner in src/c_api.cpp builds a geometric, graph-only renderer with retainObservationBuffers=false and installs MetalHybridObjectTracker::observationProgram. A separate retained captureRenderer may be built for media; its output is not the policy observation. The tested synchronous producer uses a different retained fast renderer and sampled WorldFamily, so its returned batch cannot simply be labeled as the current policy camera frame.

MetalWorld.mm encodes the generic task observation and observation-time body projection, calls the device visual encoder, then encodes policy/action, physics and task completion into the same command buffer. The direct-winner observation consumes geometric winners on the device before host command completion can be known. MetalWorldSubmission::wait waits for the entire command and only then checks Metal completion, reads status and validates the result. The test producer proves that its own render and readback calls have completed before its wrapper publishes a host copy; it does not produce a per-environment task-step success signal. Pixel FRAME validity, an empty winner plane and a successful renderer encode are not substitute completion signals.

A bounded single-step integration can preserve current observation timing by using a transaction owned by the submission, with accepted resources and candidate resources distinct. Observation-time body projection, visual winners or planes, sampled metadata, cadence, actor and tracker histories, policy effects, physics state and caches must all target candidate storage or an equivalent safely discardable arena. A device marker written after each environment render can record that the capture work was encoded and reached that point; it remains provisional until the enclosing command completes successfully. Under this simulated renderer one successful command can establish that all marked work completed, but it does not supply independent device failure for one environment or represent a physical camera. Host-visible per-environment physics outcome must be taken from the validated step status and all applicable checks, not from the capture marker alone.

On command error or validation failure, discard every candidate and keep the last accepted state and capture generation untouched. On successful command and valid statuses, construct the next accepted batch from the prior accepted batch plus the candidates of accepted environments; rejected environments retain their previous state. The merge itself must write a new unpublished arena, since a failed merge command could otherwise partly overwrite accepted buffers. Only after the merge command succeeds may the owner atomically publish the matching physics, actor, tracker, frame, metadata and cadence generation under an ownership lock. If a merge or allocation fails, retain the prior generation and report failure. Automatic terminal reset must follow the current task contract and be included in the same per-environment candidate; a retry that suppresses reset requires a separate test-only contract.

The transaction must retain its renderer/tracker, command and all candidate buffers until completion, including when a submission is moved, abandoned or destructed; the current callback has a borrowed raw context and cannot supply this lifetime. The accepted owner must exclude concurrent submissions or version candidates against their source generation. Multi-step submissions are outside the first slice: each step currently consumes state inside one command, so host-side per-step commits cannot be inserted without a device-visible candidate/accept sequence or separate commands. Failed-step and device-error tests must check exact accepted bytes and independent continuation, with actual command failures separately from pre-submit errors. A forced marker or fixture-supplied status is insufficient.

An alternative host-produced captured frame would require a new timestamped observation input path with an explicit immutable frame and status, observation-time alignment to the correct state, and a defined missing-frame policy. Replacing geometric-winner input with that frame changes the observation contract and requires a fingerprint/version migration and old-policy rejection; it is not established by the synchronous render result. Physical camera calibration and real-world sensing remain separate qualification work.
