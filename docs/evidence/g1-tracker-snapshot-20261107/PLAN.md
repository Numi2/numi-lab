# Preregistered tracker snapshot and visible-target feasibility

This is an isolated test-owner instrument, not a production patch. A new method blits the private object-track and masked-depth history to fresh shared buffers after command completion and records the host observation and last-sensor sequence. The added method never writes tracker or renderer state. The isolated library reuses unchanged objects from the corrected historical owner; the two owner patches and exact build commands are retained here. Production automatic reset and failure handling are unchanged; no no-reset retry is attempted.

The previous fixture had an actual environment-0 contact-capacity failure but no established visible target. Here five coincident bodies in environment 0 aim to exceed capacity eight, while a sixth target in both environments is placed in the camera view, with enlarged synthetic authored geometry to produce a resolvable image. This is a visibility hypothesis, not an established witness. The actor is the same deterministic, exactly bound zero policy. The same two environments, three-step control, first-failure stop, 16 by 9 masked-depth renderer and 10 Hz sampling are used.

Run two separate processes in the order instrumented then no-snapshot control, each with a 120-second timeout; retain full status, actor rows, exact float bit snapshots, stderr, timestamps, shader, binary, library and asset hashes. A CPU analysis checks the exact object-track history layout in HybridRenderer.metal: each environment has trackHistoryLength times tracks times two float4 records. A target is visible only if a position-confidence w for target track 5 is exactly 1 in the relevant environment; background depth or a nonzero suffix is not proof of visibility. The mixed-failure gate requires all control steps successful, an actual environment-0 contact-capacity rejection and environment 1 success on the same step. Compare before/after private histories bitwise for each environment and report cadence; compare instrumented and uninstrumented actor/status streams at printed precision to test instrumentation neutrality. Preserve every failed prerequisite; no reruns in this study.

Because failure is induced on the first step, a changed failed-environment tracker or depth history demonstrates pre-acceptance mutation for that one case only, not the complete consequences of retry or an accepted-history rollback test. If visibility is absent, report any state change and host cadence as preliminary, without asserting a real target was tracked. Automatic reset remains enabled; this study stops before the next step. No claim about deployment-valid perception, a general repair, or performance follows.
