# MetalWorld rejection after a successful visual encode

On Apple M6, a two-environment native Franka task and real object tracker reproduced the pre-submission leak through `MetalWorldContext::initializeResidentState`. The fault arm's tracker successfully encoded; the subsequent injected device-action callback returned false. MetalWorld rejected that submission with no ticket and reported `device action program rejected the native task submission`. A retry using the same inputs and context completed with zero reported failed physical steps, but its renderer metadata reported sensor sequence 1. The matched no-fault process completed with zero failed steps and sequence 0. The unchanged sequence-0 assertion fails in the fault arm.

The independent audit compared all 15 ordered body names between the compiled runtime and visual-world template in both arms; they match. That establishes this name/index correspondence, not equivalent calibration or physical models. The test uses one control step, a zero-filled device action, implicit drives, an all-zero reset-mask stream and disabled CCD. It does not exercise a post-commit GPU failure, rejected individual environments, retained GPU sensor-history rollback, learned policy quality, or calibrated visual or contact behavior.

The initial fixture compilation failed because the action callback lacked its required `noexcept`; the next two setups failed native preflight before callback execution because implicit drives and then a reset-mask stream were missing. Those failures are retained, alongside the first successful reproduction and its independently repeated body-name audit. Source was main `aebe27e76`; since the last native library build only evidence files changed. The archive includes source, executable, library, shader, logs and hashes. An independent extraction verified its manifest, body-name comparisons, exit codes, failure message and retry sequences. Archive SHA-256: `4674fd5f36671ef550f387f844aa71a09e81c07ceaf406c9ed4d068218d730c5`.
