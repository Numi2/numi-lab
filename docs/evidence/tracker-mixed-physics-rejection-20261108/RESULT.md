# Mixed-batch physical rejection and visual observations

**Diagnostic; physical-step observation rollback is not qualified.** On Apple M6, at source commit `68d7f1afab74b070e21c5880c5bc5d87b8b479ec`, a real mixed-batch MetalWorld contact-capacity failure was reproduced while the visual object tracker was active. This is a deliberately low-capacity test, not a benchmark or a claim about normal-capacity failure rates. The interval-local CCD and augmented-Lagrangian options were not enabled.

The one-step fixture used two Franka environments with the object in environment 0 near the workspace and the object in environment 1 elevated; clutter was elevated in both. With raw contact capacity one, environment 0 required six contacts and reported contact-capacity overflow; environment 1 succeeded. MetalWorld published the evidence, reported one failure and one success, and returned the GPU-environment-failure status. `mixed.log` records this no-dropout run.

The preregistered two-step follow-up added deterministic camera-depth dropout of 0.35, retaining the same collision setup and using a 20 ms control interval and a 50 Hz sensor cadence. It produced two capacity overflows in environment 0 and two successful steps in environment 1. Every failed transition was explicitly marked `done=1, physics_error=1`, reason 5; the other two transitions were `done=0, physics_error=0`. The renderer metadata advanced to sequence 1. Each independent repeat produced identical actor-output bytes, SHA-256 `984d322b99a0b7212e08c408ef67d4e79d54be73c0c9d3cd7ae1a45f714a6718`. Logs and a decoding script are retained here.

The failed environment received a newly sampled observation on the next control step, and all three tracked-history slots contained that new observation. Source inspection explains an important confound: the task marks physics error as a termination, and on the next control step it resets the environment and refills the history. The new frame therefore cannot distinguish an improperly retained failed-step observation from the expected initialization of a new episode. The successful environment retained its previous frame in two slots and added a new frame in the last slot. These observations establish the current reset and shared-cadence behavior; they **do not prove a tracker rollback defect or prove physical-failure rollback is correct**.

The tracker encodes history writes before physics acceptance and maintains a shared host-side observation/sensor sequence. A safe mixed-environment transaction cannot be established merely by rewinding that shared sequence, because accepted environments must progress independently. The MLX policy worker currently rejects a rollout pack containing any physics-error transition; this observation does not establish that every other learning or inference consumer does the same. The failed transitions in this fixture have nonzero reported reward even though they are flagged, so consumers must honor the failure flag. No claim is made about recurrent policy state, masked-depth history, retries without episode reset, recovery, production workloads, or deployment-valid perception (this fixture selects using simulator instance identity).

## Reproduction and provenance

The input patch `diagnostic.patch` applies to `apps/visual_platform_probe.cpp` at the source revision above. Apply it to a **scratch copy**; it is a diagnostic patch, not a production change. Build that copy as Objective-C++23, linking the same MetalRobo dynamic library and Foundation/Metal frameworks, then run with `NUMI_TEST_WORLD_TRANSACTION=1` and `NUMI_TEST_RESULT_PREFIX` set to a writable path. The patch asserts the four expected per-environment outcomes and saves actor outputs. `python3 analyze.py` decodes the retained result. `PLAN.md` records the fixture and gating choices made before the two-step run; `two.log` is the first two-step run and `two_verified.log` is the repeat with explicit status assertions. `replay.log` records a third run from the retained patch applied to a fresh source copy and a separately rebuilt executable; its actor output was byte-identical to the retained actor data.
