# Main visual depth validity repair

The main identity-masked visual depth path now admits a materialized pixel or edge neighbor only when both FRAME and DEPTH validity are set. A direct geometric-winner sample is no longer selected when its sensor depth measurement fails. A missing materialized frame cannot be populated by edge flicker. The existing edge-flicker option still permits a frame-present invalid pixel to receive a valid neighbor's depth; this intentional corruption is not an actual sensor measurement. The direct-winner shortcut does not expose a separate frame-presence signal, so its missing-frame behavior remains unqualified.

This changes visual observations. The task compiler adds a discriminator to the visual observation fingerprint. Old visual policy contracts are rejected rather than silently used with the changed observation semantics; nonvisual fingerprints remain unchanged in the matched Franka fixture. This is not a policy migration or trained-policy qualification. Users must retrain or explicitly rebind only after evaluating their policy against the revised observations. The permanent compatibility test uses retained pre-change zero-policy fixtures and verifies the old visual pack fails with `incompatibleContract`, the old nonvisual pack compiles, and an explicitly rebound visual pack compiles without actor shape change.

## Native evidence

The fixed main-owner regression compared exact pre-change and candidate shaders on Apple M6. Valid selected and unselected controls passed in both arms. At 4x2 and 20x20, respectively, the old shader emitted 7/16 and 425/800 false near values for far-clear, depth-invalid samples with deterministic additive noise; the candidate emitted zero. With DEPTH but no FRAME, the old shader emitted 16/16 and 800/800 near values; the candidate emitted zero. A mixed-frame, forced-flicker test caught three wrong missing-frame and three wrong frame-present neighbor outputs in each image size on the old shader; the candidate passed all. The selected direct-winner sensor-dropout case had 7/16 false near samples in the old shader and zero in the candidate. The direct test does not independently represent missing frame. These are synthetic kernel controls, not sensor calibration.

A second native comparison used the rebuilt full product shader and main runtime on a real 160x120 renderer with four Franka environments. The normal scene contained 3,700 valid-depth and 186 geometry-without-depth pixels. Against the independent CPU reference, the candidate had zero pixel mismatches with edge flicker both off and forced on; the old shader differed on 186 with flicker on. The full-dropout scene contained 3,886 geometry-without-depth pixels and zero valid-depth pixels; both arms matched the reference in that specific no-added-noise renderer case. The accepted instance ID was derived from simulator geometry, so this test uses oracle selection and is not deployment-valid perception. The raw planes and scripts are retained. Actual timing prints are diagnostic, not a benchmark.

The rebuilt product passed `metalrobo.visual.masked_depth_validity`, `metalrobo.visual.observation_fingerprint`, and the existing `metalrobo.runtime.task_program` CTests. The existing native visual-platform probe also passed on two environments and two views. `product-renderer-inputs.sha256`, pre/post checks and run output identify the source, owner dylib, full shader and probe. The matched policy exercise and fixed synthetic regression record both failing controls and passing candidate. GPU work ran without matching competing native test jobs; no speed claim is made.

## Boundaries and provenance

Plans were written before each bounded experiment. The first standalone shader was copied from the integration checkout, which includes unrelated presentation differences; `BRANCH-PLAN.md` records the subsequent exact-main rerun. Initial candidate and amended edge-flicker evidence remain separate. The main product source change was restricted to the depth kernel and observation fingerprint. No CCD or contact experiment was enabled.

The changes do not repair or qualify sensor/history restoration on rejected physics, mixed-environment acceptance, command failure after submission, recurrent-policy rollback, real camera calibration, sensor latency, deployment-valid object selection or held-out task performance. Those remain separate integration work. The older research evidence includes a failed pre-submit transaction and a narrow unpromoted guard; this depth repair does not supersede them. The product branch still requires integrated-release qualification.
