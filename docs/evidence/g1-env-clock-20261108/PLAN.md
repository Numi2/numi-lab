# Accepted visual clock, standalone prerequisite

This isolated slice introduces a four-word per-environment record: accepted observation count, last accepted sensor sequence, accepted capture-step identity, and an opaque capture-time word. The host proposal uses exactly the current tracker's float-configuration-to-double sample expression. On a held frame it preserves the last capture identity and timestamp. The GPU commit kernel selects the entire proposed record only when both world and contact statuses indicate success. It is a standalone owner-shaped primitive, not yet connected to a renderer or rollout owner; it does not justify mixed-environment continuation. The 32-bit all-ones sentinel is reserved and overflow fails closed. The timestamp is deliberately supplied by the caller: its physical and reset semantics have not been established. Reset proposals fail closed rather than changing the existing production reset contract.

The CPU test exercises 10 Hz sensing at 20 ms through a sample boundary, mixed acceptance and a divergent sample/hold decision, 50 Hz sensing, invalid rate, reset and overflow. It does not execute Metal. The GPU test is preregistered to run once with a 120-second timeout. Four environments cover success, world-only failure, contact-only failure and both failures; compare all four uint32 words exactly against proposed records for success and prior records for failure. Retain process timestamps, outputs, exact binary/library/source hashes and any failure. This direct kernel test does not run physics, rendering, stochastic seeds, resets or continuation. The research divergence guard remains enabled.
