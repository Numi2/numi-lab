# Preregistered 25 Hz real-status sample/hold diagnostic

The isolated task uses the existing two-environment moving-target fixture at a 20 ms control step, 25 Hz nominal sensor rate and 5 mm depth noise. It keeps the original single-step observation/physics restoration hook and its fail-closed divergence guard. A separate device-visible per-environment research clock computes candidate sample decisions using the tracker's existing double-precision timing formula, then commits those records using the actual GPU world/contact statuses. It is not the batch renderer's owner clock and does not change its scheduling. Capture identity in this diagnostic is copied from the renderer's actual existing single-step frame/time 0/0; no new physical timestamp semantics are inferred.

Require two real accepted nonterminal steps followed by the known environment-0 contact overflow and environment-1 success. At step 3 both proposals should sample sensor sequence 1; the rejected environment must retain `(accepted=2,lastSensor=0)` while the successful one must commit `(accepted=3,lastSensor=1)`. Their next counterfactual, pre-reset proposals should be `(sensor=1,sample=true)` and `(sensor=1,sample=false)` respectively. Do not submit that fourth step: the terminal environment's actual next step normally resets, and a no-reset retry is a separate unsupported mode.

After the mixed result, record the retained prior, current and separately rendered sensor-1 reference planes from the same observation-time projected bodies. Require the failed env's depth, ID, validity and camera words to equal its prior accepted frame, the successful env's new words to equal the separate renderer reference, and the target visible before the failure. Record changed-word counts so unchallenged fields are explicit. Track history and global renderer metadata are retained but are not claimed to have independent metadata ownership. Run once with 120 seconds, preserve all output and exact word snapshots, and check all pinned inputs before and after. The experiment does not implement or test real post-divergence rendering, reset, independent renderer metadata, actor history replay, masked depth or command-buffer failure. The divergence guard remains enabled.
