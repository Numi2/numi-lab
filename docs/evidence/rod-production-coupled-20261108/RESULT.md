# Published Metal rod versus the coupled reference

On Apple M6 at source revision `29e84f66399729715d88dfe17588533b4587d3ce`, the existing standalone Metal rod path was evaluated against the previously checked coupled straight-rest DER step. At both the ordinary 24-sweep setting and the 128-sweep diagnostic setting, **2 of 12** cases reported success and published, while **10 of 12** returned GPU status 4 (`MR_ROD_GPU_DID_NOT_CONVERGE`) and did not publish. **None of the twelve passed the full completion and physical gates.** The two accepted cases are the already-exposed three-node symmetric prestretch and its 100 nm microbend variation; the ten rejected cases are the exposed curved/twisted inputs. This is not a randomly sampled production workload.

The accepted straight case publishes a middle-node displacement and velocity error of 0.000437637 m and 0.437636 m/s, respectively. Its two support-force errors are 0.088758 N and 0.088722 N against approximately 0.089379 N reference reactions, far outside their 0.000894 N limits. Independently differencing the native DER energy at the *published* state yields a local free-node momentum residual of 436.749 m/s; the two finite-difference scales agree within 1.51e-8 m/s. The microbend has effectively the same error. This reinforces the prior false-acceptance witness with an independent local force check; it does not establish that the reference is a physical-material calibration. The actual positions, velocities, twists, reaction values, status and every computed check are retained per case in `results.jsonl`.

Both complete 24-case matrices were byte-identical. The prior case-level velocity perturbation is not sufficient calibration because the unperturbed cases already fail. A separately registered follow-up used an unloaded straight rest configuration. It published with zero middle-node local momentum residual; injecting 0.002 m/s into that residual made it fail the 0.001 m/s check. Two native runs were byte-identical. This calibrates that narrow linear residual control, not angular sensitivity, a general force certificate, or production accuracy.

The untouched owner build reported no work, and `pretrial.sha256` records the probe, host library, metallib, plans, input and reference identities before the matrix; `owner-source.sha256` records the relevant source and header identities afterwards. The follow-up calibration was registered after the matrix, and neither the input selection nor numerical gates were changed. Both experimental CCD and augmented-Lagrangian options remain disabled.

This is a standalone one-step host publication and CPU readback test, not persistent MetalWorld state, contact, rollback, performance, anatomical or surgical qualification. The current production false acceptance is **not repaired**. The next change must both prevent publication of the demonstrated invalid state and complete ordinary loaded motion with correct forces: the earlier research-only stretch-stationarity guard rejects this state but also rejects loaded cases, so it is containment evidence rather than a finished solution. The coupled reference and native gradients provide independent tests for a full position/twist solve and its reactions.
