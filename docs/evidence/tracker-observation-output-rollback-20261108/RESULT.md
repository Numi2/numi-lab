# Tracker output on a rejected physical step

The tracker previously restored private and actor histories after a failed physical step but left its visual writes in the actor output row. The existing two-environment track/masked-depth regression, strengthened before the repair, fails on the unchanged runtime with `failed environment actor observation was not restored`. `baseline-failure.log` retains that failure. An initial incorrectly named CTest selector found no tests; it is retained separately and is not counted as validation.

The tracker now snapshots the current control-step output region before visual writes and, for a rejected environment, restores its pre-tracker row. For a rejected step that also resets, the old visual values may belong to the previous episode: track fields instead become zero and masked depth becomes far/no-return with zero features; nonvisual fields remain as they were immediately before tracker observation. Accepted rows retain their visual updates. The output offset and size, as well as the selected reset-mask range, are checked before the GPU copy; the binding offset check uses a widened addition. The backup is private to the submission and introduces additional memory and GPU work, whose cost is not measured.

The first candidate restored old rows even on reset, exposing stale episode data and failing the existing reset control. The [amendment](RESET-AMENDMENT.md) and `visual-first.log` preserve that failure. The revised behavior initially failed the sampled-reset test because that test still expected a visible candidate on the failed reset; the assertion was updated to require invalid output on the rejected reset and the following stale frame. `visual-reset-expectation.log` and the final successful run preserve the sequence. An intermediate build failed on a missing test include; that compiler output is also retained.

On Apple M6, all 22 `metalrobo.visual.*` tests pass on the final main build. The mixed tracker test exercises object tracks and masked depth, with a failed environment restored and an accepted neighbor advanced. It also checks nonzero output offset, prefix/suffix canaries, and out-of-range and overflowing offsets. The GPU status-layout test covers world and contact failure combinations, contact-disabled stale statuses, reset/non-reset output handling, track/depth sizes, nonzero output offset and canaries. Existing host-abort/retry, lease, reset and sampled-frame controls also pass. These tests do not simulate GPU command-buffer failure.

The separately planned real 30-step MetalWorld probe records the full pre-tracker, post-tracker and post-physical output row on each of two environments. Its intentionally constrained contact capacity produces 55 accepted and five rejected environment-steps: three rejected without reset and two rejected with reset. All accepted rows equal their post-tracker capture; rejected non-reset rows equal their pre-tracker capture; rejected reset rows preserve nonvisual fields and clear all visual track slots. All three non-reset failures had a changed tracker candidate, and 53 accepted rows changed, so those comparisons exercise actual writes. Three control steps have mixed outcomes. Two full runs match in q/v, scene, actor output, status, reset masks, actor history and all captured output rows. The q/v, scene, status and reset arrays also match the earlier retained pre-repair fixture. This world probe uses object tracking and oracle instance identity; masked-depth output is tested by the direct fixture, not by this full physical rollout.

[PLAN.md](PLAN.md), [REAL-WORLD-PLAN.md](REAL-WORLD-PLAN.md), build logs, source generator, native traces, analysis and hashes are retained. `world-captures.tar.gz` contains both the initial and final captured runs; `python3 analyze_world.py world-captures/final` from this directory after extraction checks the final run against the paired samples and the adjacent older baseline evidence. The final physical run was repeated after adding the reset-buffer bounds check. The prior run and pre-check library hash remain recorded, but the prior library binary was overwritten by the final rebuild. The probe is read-only and does not establish all hidden owner/cache bytes.

This repair is deliberately scoped: its snapshot occurs after generic task observation, and a rejected rollout remains marked as a physics error. Per-environment accepted sensor time, rendered-pixel ownership, generic task state, actual device-command failure, complete episode replay, deployment-valid perception and trained task skill remain unqualified. The two experimental collision/contact options stay disabled.
