# Owner trace: requirements for mixed-environment visual continuation

This is a source trace of the isolated `numi-g1-transaction-candidate-owner-20261107` derived from the retained historical owner, not a new runtime result. The changing-pixel single-step evidence and all its limits are in `../g1-transaction-moving-pixels-20261107/RESULT.md`.

`MetalHybridObjectTracker::encodeObservation` in `src/metal/MetalHybridRenderer.mm` increments `observationSequence` on the host before the command has established physics acceptance, computes one sensor sequence with `floor(sequence * timestep * nominal rate + 1e-6)`, and conditionally encodes an entire batch render. `lastSensorSequence`, `HybridDeviceStateBatch.sensorSequence`, frame index and capture timestamp are batch-wide. The renderer's `activeMetadata.identity` and timing are likewise a single batch record. Renderer shader `frameSeed` consumes this shared frame/sensor sequence for noise and dropout; `fastSubpixelOffset` also consumes the shared sequence when multiple samples are configured. Thus restoring individual held planes and advancing independent counter values alone does not establish correct independent sampling, random streams, timestamps or metadata after the first mixed outcome.

The object-track kernel advances each environment's history on every observation, including when a frame is held, using the control timestep to compute the velocity. The masked-depth kernel uses per-environment episode step/index for its ring and corruption, but its direct-winner path can also call the renderer's batch-seeded `frameSeed`; its history and winner sources were not included in the passing fixture. A solution must preserve the existing intended held-frame observation semantics rather than silently changing track update frequency.

Task reset is independently owned: `LocomotionTask.metal` sets a per-environment reset mask based on task initialization, terminal status and requested reset before visual observation; the tracker consumes that mask. The host tracker `reset()` instead resets all environments and the shared cadence. Neither may be replaced with an inferred physics retry. The research prepare hook checks equal accepted counters, and the finish hook restores the rejected environment after task completion; next-submission refusal was not tested in the preceding run.

A bounded continuation implementation needs a per-environment accepted observation clock and last accepted sensor sample, device-visible before observation; a render path that uses each environment's own sample decision and timing for geometric frames, stochastic sampling and metadata; and atomic per-environment selection of frame, camera, tracker, actor and applicable ring history after physics/task completion. Reset must have a documented relationship to that clock, with the task's real reset mask as authority. Command failure must invalidate or restore the whole in-flight session; GPU status is not sufficient on its own. Publishing one shared metadata record cannot represent different sequences or capture times, so a caller consuming metadata needs an explicitly per-environment representation or the research mode must fail closed.

Before removing the divergence guard, register a deterministic mixed-success continuation study with nonzero sensor corruption and a rate below the control rate so sample/hold decisions differ between environments. Compare both environments, including exact sample identity, timestamps, image planes, actor/tracker history and RNG-derived pixels, against separately controlled single-environment sequences with identical identity and reset inputs. Distinguish the production automatic-reset path from a separately enabled test-only retry; neither was established by the single-step study. Exercise masked-depth rings and command failure in separate gates. No change to production publication is proposed by this trace.
