# Tracker physical-step history restoration

At source commit `ed0c63c71`, MetalWorld invokes an optional observation-owner callback after physical substeps for each control step. The native tracker snapshots its object-track and masked-depth private histories before each observation, then restores the snapshots only for environments whose world or contact status reports failure. The buffers used for snapshots are private to the submitted command. Existing observation callbacks without the optional hook remain supported; a callback that supplies the hook must also supply the begin/finish pair. This extends a C++ structure: clients must rebuild against the matching headers, library and shader.

This repairs the two private history buffers, not the entire sensor/policy transaction. The host sensor cadence is still shared; frame metadata, rendered buffers, task actor history and recurrent policy state are not restored by this change. It does not repair a GPU command that fails after partial execution. The host lease ends on commit, so callers must serialize tracker/renderer use across in-flight commands. Automatic reset after a physics error prevents the retained rollout from establishing a matched retry without reset. These are outstanding requirements, not qualified behavior.

## Native qualification

The preregistered [failing baseline](../tracker-physical-boundary-20261108/RESULT.md) was a 30-step two-environment Franka fixture with a deliberately tiny contact capacity, no CCD, and 35% camera-depth dropout. After previously accepted steps, environments had mixed outcomes on steps 13 and 26; five environment-steps failed in total and 55 succeeded. In a separately built runtime differing only by a read-only test accessor, GPU snapshots show all 5 failed object-track histories equal their own pre-observation values after physics, while all 55 successful histories equal the post-observation values. The same check passes with two bindings rather than one. `source-equivalence.txt` records the source comparison; these direct-buffer observations do not use the exact production binary.

A non-instrumented main binary and the combined integration binary both completed the same fixture. Their q, v, scene, actor and world-status arrays match the previous non-instrumented baseline byte-for-byte. The instrumented run matches those arrays too. This establishes the checked outputs, not unobserved state or performance. The negative control and all prior failure evidence remain retained. The fixture uses simulator instance IDs, so it is oracle perception, not deployment-valid object detection.

On Apple M6, both the main and integration builds passed 12 native visual tests. The tests include 18 GPU restore-layout/status combinations with empty and nonempty track/depth layouts, mixed world and contact failures, and stale contact codes ignored when contact is disabled; an actual tracker callback exercise checks object tracks and masked-depth history through reset and mixed synthetic world statuses, including the no-contact buffer case. The integration fixture checks that MetalWorld invokes the hook. A host rejection after this hook followed by retry produces q/v/scene/actor/status bytes identical to its control. The legacy callback without lifecycle hooks also passes a private-heap rejected-submission retry against its control. Fresh and resident host-abort tests continue to pass. A first build attempt failed because the test used a deprecated Metal library method; `rebuild2.log` and the resulting incomplete `ctest.log` are retained, followed by the corrected successful tests.

`analyze.py` checks the saved arrays, both history traces and the prior baseline. The two standalone test harnesses are retained as `probe.cpp` and `two_bindings.cpp`; they use the read-only accessor patch from the baseline evidence. `production_probe.cpp` exercises the same scene without that accessor. Native debug and normal build hashes follow; `b766746cb4ba197abbf46a9a9c9711df7d2873ed` is the combined integration revision.
