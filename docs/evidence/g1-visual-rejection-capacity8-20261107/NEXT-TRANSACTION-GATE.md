# Required owner instrumentation for rejected-environment restoration

This is a proposed diagnostic, not an implemented repair or a result. In the historically matched owner, MetalWorld.mm encodes task observation, projected bodies, device observation and policy before executing the physics step. MetalHybridObjectTracker::encodeObservation increments the host observationSequence, calculates sensorSequence, optionally encodes rendering and sets lastSensorSequence at encode time, before physics acceptance. The object-track history and maskedDepthHistory buffers use private Metal storage; the rendering winners, depth, identity, validity and camera buffers also carry held-frame inputs. The observation callback receives neither per-environment accepted status nor a commit or rollback callback. A single host sequence controls the batch. reset() clears the whole tracker histories and both host sequence counters; it does not establish an independent rejected-environment rollback. The public rollout API exposes actor output and transitions, but no private tracker snapshots or explicit failed-step retry.

The smallest diagnostic needs an owner-only test hook that, after each completed command buffer, blits exact per-environment object-track and masked-depth histories plus the held winner, depth, identity, validity and camera slices into shared readback; records host observation and sensor sequence, render uniforms and actor-history slices; and tags every snapshot with environment, completed step, reset mask and actual GPU status. Slice layout must be taken from the actual shader indexing, not assumed from allocation sizes. Snapshotting must not mutate the production buffers and must have a no-instrumentation control.

To test rejection after meaningful history, first establish an actually visible tracked target and take at least one accepted sensor sample. Then use a fixture-only owner injection at a defined pre-physics boundary to cause an actual capacity overflow in one environment, leaving its pre-observation physics and sensor state identical to the reference; capture the GPU per-environment results, histories and actor state immediately before and after rejection. Restore the fault condition without using a reset, retry the same state, and compare bitwise against a no-failure reference while an unaffected environment keeps advancing. The fixture must separately validate that the injection does not alter sensor state, that physics actually rejected, and that automatic reset has not replaced the rejected state. Current API automatically marks physics-error transitions done and requests reset, and current resident state offers no public isolated scene mutation or retry operation, so this requires a tightly scoped test hook at the owner or a distinct low-level owner fixture.

A production repair requires more than this instrumentation: isolate candidate tracker and masked-depth history, held-frame data and cadence per environment; publish them only with each environment's accepted physical step; preserve the corresponding task actor-history transaction and reset semantics; and make command failure atomic. Shared render scheduling and host-only counters cannot express one environment retrying while another advances without a separate accepted per-environment cadence. Qualification must cover mixed batches, real visible changes, multiple steps across sensor-sample boundaries, reset, failure before and after rendering, command or encoding failure, and exact retry against reference. This experiment uses oracle instance-masked depth and cannot qualify deployment perception.
