# Mixed-environment publication feasibility after first-upload abort

This separately registered gate reuses the unchanged probe and host-only CandidatePublication helper from franka-staged-publication-20261108, with the isolated single-step upload-abort guard owner from franka-upload-abort-20261108. The original control failure and raw transition trace remain evidence; the new owner restored the first-upload fingerprints in an independently tested first-step retry. This gate tests whether that correction permits the previously blocked mixed-status hypothesis; it does not overwrite or reinterpret the original run.

Pin copies of the original probe, CPU unit, guarded dylib, shader and task asset by SHA-256 before GPU use and verify them after. The original probe and source are unchanged. Run the CPU helper unit, then independently initialized control and mixed Franka processes, in that order, with 120 seconds per process, stopping on the first failure. Both use a zero policy, synthetic direct-winner observation, two environments and capacity one. Each rejects its first submission using the real owner hook and requires the candidate to refuse publication. The control places both objects away from contacts in both environments. The mixed arm changes only environment 0 to overlapping objects near ground; actual per-environment raw-contact overflow is a hypothesis, not a guaranteed failure. Retain every status, required contact count and failed prerequisite.

A usable comparison requires completed and validated results with both control environments successful, mixed environment 0 failed and mixed environment 1 successful. Only then examine rejected-environment sentinel preservation and exact env 1 actor bytes against the independently initialized control. Control/mixed process success alone does not establish this; retain the byte-comparison report. The sentinel is not a previous accepted frame. If transition validation rejects a mixed physical result, report that as an unresolved prerequisite, not as mixed publication success.

This is a host-only projection of observation vectors, not owner-level atomicity. It does not qualify resident physics, actual tracker/actor history, frame or cadence rollback, automatic reset, real camera, post-commit command errors, asynchronous callbacks, or retry after environment failure. No GPU failure is injected. Production defaults are unchanged and the candidate remains unpromoted.
