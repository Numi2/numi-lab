# Preregistered isolated owner transaction-boundary hooks

This preparatory owner copy adds opt-in, thread-local research callbacks before task observation and after physics/task completion. They receive borrowed actor-history, actor-output, reset, task-state and world/contact-status buffers for the same command buffer and environment count. Installed hooks explicitly reject multi-control-step submissions. With no hooks installed, the existing path has no callback work. The test callbacks only check the host encode-call order and buffer availability; they do not encode GPU work, stage state, suppress resets or repair a transaction.

The executable is the previous identity-matched visible target and delayed mixed-failure fixture, using the same exact shader and corrected visual assets. Run one process under a 120-second timeout; retain every row, frame/history bits, hook calls, identities and timing. Require a prepare/finish pair for each attempted single-step submission, visible target and the prior mixed-failure result. Compare exposed actor/status text to the prior no-hook run; any mismatch or callback failure is retained. This establishes only research hook placement and bounded neutrality, not GPU completion ordering, private-history restoration, per-environment cadence, held-frame publication, retry, or production readiness. The registry is a diagnostic single-thread facility, not a production API.
