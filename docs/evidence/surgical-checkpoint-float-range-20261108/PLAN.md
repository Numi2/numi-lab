# Surgical checkpoint float-range integrity

Question: can the handoff state reader accept a finite textual number that overflows an FP32 state field? The current parser validates the input as finite double but narrows q, v, needle, rod-node and rod-edge values to float. Before modifying the loader, use the retained synthetic tissue-rest checkpoint, copy each input to a new scratch directory with the unchanged Matter payload symlinked read-only, and replace one value in each affected field with 1e100. Invoke the existing no-step restore command for each case and retain return code and complete output. The unaltered checkpoint must pass. Require rejection before physics/state acceptance for each malformed input; accepting a value that became infinity is a loader defect, even if a later subsystem happens to reject it. This is a synthetic integrity test, not the earned surgical bridge or a physical simulation.

Implement a checked finite FP32 conversion at the loader boundary, preserving double precision where the destination is double. Add permanent negative cases for each float field, run the original integrity suite and restore/hold controls, and verify the original checkpoint and Matter bytes were not changed. The experiment does not claim full owner-state atomicity, exact coupled rollback, quaternion validity, physical calibration or surgical continuation. Both experimental CCD and AL contact options remain disabled.
