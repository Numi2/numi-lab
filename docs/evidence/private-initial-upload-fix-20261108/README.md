# Private initial-upload abort: integration evidence

This focused change is based on bb58f524353dc90b84c327908b26aeaaea5194ba. The final source and tests match the blobs used in `upload-private-fresh-ctest-20261108`: fresh CMake build, private-only initial and populated-cache CTest 2/2, exact hashes and logs. Its guard applies only to private-heap preference, an initially empty immutable binding cache, and configurations without Millard, multicopter or device-physics programs. It prevents a failed pre-submit encoding from advertising uncommitted initial model/task/policy uploads. Guard construction occurs after arena allocation/replacement; it disarms after commit returns.

The predecessor `initial-upload-limited-main-20261108` records an unmodified-main private baseline that failed after an actual pre-submit callback rejection and a guarded retry byte-identical to independent control; `nonempty-upload-abort-20261108` records the already-bound same-model negative/control. Those tests used an otherwise equivalent predecessor without the final private-preference predicate; their exact identities and scope are retained. The candidate-linked full-step CCD and kinematic scripts in `initial-upload-owner-regressions-v2-20261108` also used that predecessor; their existing rejected CCD cases and inactive-cache reset discrepancy are explicit in their results. `initial-upload-shared-baseline-20261108` retains the separate preexisting shared fixture failure; final code does not change shared behavior.

There is no claim for cache replacement on a previously bound model or program, shared mode, arena mutations before the guard, device failure after commit, excluded program families, mixed sensor state, contact-force accuracy or performance. Complete earlier failed, exploratory and historical evidence remains on the research branches; no production promotion is implied by this commit.
