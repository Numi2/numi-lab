# Visual observation pre-commit lease

At source `001c607960d23c0ef8da936aa366e61ca1cb23ce`, MetalWorld now optionally acquires a submission-scoped lease from an observation program. The native object tracker reserves itself and its renderer during host encoding. If the command is abandoned before commit, its host observation and sensor sequences, direct-winner uniforms, renderer metadata and active environment count are restored. Competing renderer operations, readback, tracker reset or a second tracker lease reject during that interval. Successful commit releases the lease; this is not a GPU completion or physical-acceptance callback. Existing callback implementations without lifecycle hooks remain admitted; an incomplete pair of hooks is invalid. C++ clients must rebuild against the expanded program structure.

The original [MetalWorld failure](../tracker-world-rejection-20261108/RESULT.md) was reproduced against the prior native library: an action callback rejected after successful observation encoding and a subsequent valid retry reported sensor sequence 1 instead of 0. On Apple M6 the candidate and integration tree each pass 11 targeted visual/runtime CTests, including a real native task rejection after the first or second encoded observation, both from a fresh owner and from an already accepted resident, plus no-fault controls. The fresh retry reports sequence 0 and the resident retry sequence 1. In each build, independently saved q, v, scene, actor-observation and status bytes match the no-fault control for both fault positions and both owner states. The two builds also produced identical saved control bytes in this fixture. The tests verify a second tracker sharing the renderer cannot acquire its lease, an unleased foreign encode rejects until release, wrong-command release does not unlock, and renderer readback, rendering and tracker reset reject while reserved. The direct-winner regression also encodes a valid observation into an abandoned command before its normal retry.

An existing custom callback without lease hooks still passes the private-heap initial-upload rejection and byte-identical retry control. Main tests use the commit above; the combined release-integration tree is merge `b21329a67793af48fb4b77db9bdcc2560be54d2b`. Binary and shader hashes, CTest logs, raw comparison arrays, controls and fault logs are retained here. These tests use a small synthetic Franka scene and no physical performance measurement.

This is a scoped host pre-commit repair, not full sensor transaction completion. It does not restore GPU tracker or depth history after a committed command fails, handle mixed per-environment accepted/rejected physics, establish actual sensor latency, or roll back recurrent policy state. The owner and borrowed raw buffers must outlive and obey the lease; external raw-buffer writes are not intercepted. Continue with device-side acceptance-gated sensor history and matched failed-step controls, including mixed-environment acceptance and post-submit command errors. Both experimental CCD and barrier-free contact options remain disabled.
