# Candidate sensor publication and independent retry oracle

The retained native evidence in ../g1-matched-visual-identity-20261107 shows accepted visible track history changing on a physically rejected step. The current callback encodes before policy and physics; its private history buffers and host-wide cadence are changed without any later acceptance callback. MetalWorld encodes all substeps, commits/rolls back physical state per environment, then runs task completion; task completion marks physics errors done and schedules the normal automatic reset. A production candidate must respect that existing terminal/reset contract.

A scoped implementation would add a two-phase observation callback with explicit candidate ownership. Per environment, it must snapshot or double-buffer tracker records, masked-depth rings, held renderer frame and metadata, task actor-history/output changes, and sensor cadence. The pre-physics observation and policy consume the candidate. After the full physical step, an owner-encoded publication kernel uses the same per-environment physics and contact status as task completion to copy or swap only successful candidates; failure retains the accepted sensor state and does not advance that environment's cadence. The subsequent ordinary terminal/reset path remains authoritative: when a reset is actually accepted, the reset candidate establishes a new episode and history. A command-buffer or encode failure must leave all accepted state unchanged. This is a design, not an implemented repair.

Current observationSequence and lastSensorSequence are batch-wide host scalars computed during command encoding, while mixed statuses exist only later on device. A host scalar cannot represent one environment rejecting while another advances, especially when multiple control steps are encoded in one command buffer. Per-environment accepted cadence and sample decisions must therefore be device-visible and transactional; retained depth/identity/validity/camera frames must be independently selected per environment. Renderer-wide metadata and other held inputs require an explicit ownership audit, not just swapping the two tracker buffers. Any change in sensor semantics requires policy contract/fingerprint review.

The included small independent CPU model specifies a mixed acceptance, divergent cadence, no-reset same-input retry, rejected reset, accepted reset, and command-failure atomicity. It passes, but it is a specification oracle, not an owner test or evidence that Metal implements these rules. The native retry test still needs a separately isolated test mode: build accepted visible history, cause one real per-environment capacity failure, remove only the test fault while preserving the exact accepted physical and sensor state, suppress the otherwise normal automatic reset for that test only, and compare bitwise with a no-failure reference. The test must independently confirm equal pre-retry physics, frame and policy inputs, the real failure status, unaffected-environment progress and reset behavior. The existing public resident interface does not expose such an injection/removal or private-state restore, so constructing this gate requires a narrowly scoped owner test hook and further review before any production fix.
