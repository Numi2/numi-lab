# Local bend and twist law for a straight-rest rod

For the current DER model with straight rest geometry and scalar isotropic bending stiffness, the following expression matches its transported-material-frame bend energy at the tested states. For adjacent unit tangents with dot product `c`, relative twist `d`, bend stiffness `EI`, and rest Voronoi length `l`, the expression is

`E_bend = (EI/l) * ((1-c)/(1+c)) * (1 + cos(d))`.

The usual separate DER twist term remains quadratic in the difference from rest twist. The analytical gradient includes the derivative of the cosine term; dropping that coupling is the negative control. This formula is a building block for a coupled method, not a solver or a general DER replacement. It is not asserted for curved rest configurations, anisotropic sections, antiparallel tangents, contact, or topology changes.

A native CPU instrument compiled the actual `evaluateDiscreteElasticRodEnergy` implementation and evaluated 24 independently seeded 3-, 5- and 9-node configurations plus a zero-bend null and one rigid-transform control. All 26 cases passed the preregistered energy and gradient gates. Native central differences at two perturbation scales agreed with each other and with the independently coded local analytical gradients for position and twist. Maximum absolute bend- and twist-energy differences were 4.97e-24 J and 1.33e-23 J; the maximum gradient error was 0.0000414 of its specified gate. The omitted-cosine negative control was detected in all 24 seeded configurations. The sampled tangent dot products were at least 0.745, so this is not a sharp-bend qualification. Repeated native values and analysis were byte-identical.

The first analysis invocation evaluated the native data but failed serializing NumPy boolean values; `check-initial.py`, `check-initial.log` and `native-initial.stdout` retain it. The first corrected analysis used an additive absolute-plus-relative gradient gate, looser than the plan's maximum rule. That version and its analysis are retained as `check-additive-gate.py` and `analysis-additive-gate.json`; the final result uses the preregistered maximum rule and passes without changing cases or thresholds.

The output files, input cases, build and analysis scripts, executable, exact source hashes, host information, and negative controls are retained. The native implementation is the reference for this comparison; no independent physical-material accuracy is established. Future work must derive and validate the coupled tangent, address instability and precision, and test actual GPU-resident force, torque, work, contact and rollback before any production use. The retained production false-acceptance issue is not repaired. Experimental CCD and augmented-Lagrangian contact remain disabled.
