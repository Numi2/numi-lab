# Full-world masked-depth transaction check

Question: do actual masked-depth output values obey the existing per-environment tracker acceptance and reset contract during a real mixed-success MetalWorld step? Earlier evidence covered object-track output in this world and masked depth only in direct shader tests. It does not establish their combination.

Use the retained two-environment, 30-step Franka mixed-contact-capacity instrument, 20 ms steps, four substeps, a 10 Hz camera, zero actions, and CCD disabled. Keep the same renderer, initial states and object-track identity. Extend the compiled task observation with a contiguous two-frame masked-depth suffix and 24 derived features. Use the same rendered object instance identity as an oracle mask, not a deployment-perception claim. Set visual layout from actual renderer dimensions and require the nonvisual history prefix to be 102 floats. The tracker captures pre-write, post-write and post-physical-step output rows and reset masks. Run two identical trials and one capture-disabled control; bind source, executable, library, shader, input settings and revision by hash before execution.

For each accepted environment-step, post-step output must equal the post-tracker candidate. For each rejected non-reset environment-step, post-step output must equal its pre-tracker row. On rejected reset, the nonvisual prefix must equal its pre-tracker row, the track fields must be zero, both depth planes must be the authored far/no-return value, and the derived features must be zero. Independently require at least one accepted and one rejected step with changed masked-depth values, at least one rejected reset and one rejected non-reset, and at least one mixed accepted/rejected step; otherwise label the fixture inconclusive. Require all captured data, physical outputs, transition statuses and reset masks to repeat exactly, and compare the capture-disabled control physical outputs, actor output, statuses and reset output against the captured arm. Do not infer private renderer pixels or metadata restoration from actor rows. The test intentionally forces contact capacity errors and is not a performance or normal-capacity robustness evaluation. If the task cannot compile or the fixture is vacuous, retain that result and adjust the instrument only with a new recorded plan.

The requirement concerns transaction behavior, not image calibration, learned manipulation, per-environment accepted sensor clocks, recurrent policy rollback, command-buffer failure, or deployment-valid perception. Experimental directional/interval-local CCD and augmented-Lagrangian contact remain off. Stop after two captured trials and one control; do not retry a live process.
