# Already-bound private-cache abort control

Use the same compiled zero-policy Franka task and public observation callback as the initial-upload gate, but set one context slot and first require a fully successful physical submission with exactly one model upload. The cache is then nonempty, so the narrowed guard is disarmed by its source predicate. The control runs a second submission from identical authored state; the retry arm first rejects an encoded second submission with the callback, then submits that same state again. In each independently initialized baseline and candidate process require exactly one model upload throughout, successful validated final world/contact statuses, and exact final q/v/scene/actor bytes. Compare control with retry within both owners and compare baseline with candidate control. Four processes, 120-second maximum each, stop on failure and retain pre/post hashes.

This is a negative/control for an already-bound, unchanged model and private cache. No immutable data are overwritten on the rejected attempt. The preexisting shared-mode setup fails before callback, so this cannot test changed-model shared bytes or imply those bytes are restored. It does not claim nonempty-cache repair, new-program behavior, post-commit command recovery or sensor history rollback.
