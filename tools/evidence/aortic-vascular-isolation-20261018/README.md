# Dormant MPM particle guard evidence

Inactive MPM capacity particles have a valid identity and material record but are not backed by active grid nodes. The G2P pass previously attempted a grid lookup for them and could return a capacity error; the scheduler also let inactive particles participate in minimum-J observation. The source change preserves the complete accepted particle record (and the already-copied material record) in G2P, then excludes inactive particles from scheduler deformation observations.

The regression is the existing `apps/matter_physics_probe.mm --blood-mpm` run retained in `blood-dormant-gpu-regression-20261018`: the unpatched kernel fails with `dormant particle changed across a physical step`; the patched full-capacity run passes eight accepted frames and one injected rejection, with exact dormant particle/material state checks and active inventory matching the prior fixture. Its blood proxy has `materialStateStride=0`, so the stateful-material byte comparison is empty in this specific run. This does not establish fluid accuracy, clotting, or blood-transfer physics.

`byte-proof-001.log` is an independent 256-microstep control using the exact patched flattened shader through the pinned runtime source-loader path; the installed default metallib was not rebuilt. Pure generic and dense45 vascular modes both completed successfully; their normalized state difference was `1.1920929e-7`. The dormant-MPM-plus-vascular mode completed successfully, its dormant particle record compared byte-identical, and its vascular state matched the pure generic case exactly. The source and binary identities for this control are in `evidence.json`.
